# 经历记忆本地嵌入(LocalEmbeddingService)设计方案

> 状态:已定稿并实施。对应代码:`src/engine/localEmbedding.ts`、`src/cold/mem0Memory.ts`、
> `src/cold/vectorFileStore.ts`、`src-tauri/src/endpoint_proxy.rs`。

## 背景与动机

冷记忆(`src/cold/mem0Memory.ts` 的 Mem0 经历记忆)目前只有一条嵌入通道:OpenAI 兼容的
云端 `/embeddings` 端点(经 Rust 端点代理,按 `coldMemory.embedProfile` 模型档案解析地址)。
这要求用户为嵌入单独准备一个带 Key 的云端档案,且检索质量/隐私依赖外部服务。

本方案新增**本地 llama.cpp 通道**:用户手动启动 llama-server 加载任一 embedding.gguf
(如 bge-small-zh-v1.5 / bge-m3 量化版),应用对它的 OpenAI 兼容 `/v1/embeddings` 发请求。
零数据外流,无 Key,模型随意换。

## 决策记录

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| llama.cpp 接入方式 | **手动启动 llama-server,应用只填 URL** | 与 GPT-SoVITS 接入完全同款范式;零子进程管理;崩溃隔离;符合 fail-open 纪律。以后可加自动启动(纯 Rust 侧增量,TS/设置层零改动) |
| 云端通道去留 | **保留,加来源切换** | 向后兼容(老配置零迁移);本地服务没起时随时切回;默认 endpoint |
| 嵌入模型推荐 | bge-small-zh-v1.5(量化 ~25MB)够用;bge-m3 Q8(~600MB)质量上限更高 | 冷记忆检索是阵发小请求,模型权重启动即常驻;mmap 闲时可被系统部分回收 |

## 架构

```
mem0Memory.ts(按 provider 分发)
├─ provider 'endpoint'(现状不动):云端 /embeddings 走模型档案
└─ provider 'local'(新增):LocalEmbeddingService(src/engine/localEmbedding.ts)
     → requestEndpoint('coldLocal', '/embeddings')      ← 新代理 kind,gptsovits 同款「本地 URL + 免鉴权」
     → Rust endpoint_proxy 解析 /coldMemory/localUrl     ← 复用全部 SSRF 硬化(仅 POST/禁重定向/体钳位)
     → llama-server(用户手动启动)→ POST {localUrl}/embeddings(OpenAI 兼容)
```

- 前端只给 kind + 相对路径,完整 URL 由 Rust 从 config.json 解析,与既有代理契约一致。
- 浏览器预览(`!inTauri`)降级原生 fetch(开发调试用,靠 llama-server 的 CORS 头)。
- embedModel 在 local 模式**选填**:llama-server 单模型不校验 model 名,填了就带上,没填省略字段。

## 配置(`src/storage/configStore.ts`)

```ts
export interface ColdMemoryConfig {
  /** 嵌入来源:'endpoint'(缺省)云端档案;'local' 本地 llama.cpp */
  provider?: 'endpoint' | 'local'
  embedProfile?: string   // endpoint 模式必填(现状不变)
  embedModel?: string     // endpoint 必填;local 选填
  /** 本地 llama-server 地址(含 /v1);local 模式启用门槛,缺省 http://127.0.0.1:8080/v1 */
  localUrl?: string
}
```

启用门槛(`productionSettings`):`provider === 'local'` → `localUrl` 有缺省值即启用;
`endpoint`(含缺省)→ 维持现状 `embedProfile && embedModel` 齐全才启用。

sanitize:provider 非法值丢弃回缺省;localUrl 非 http(s) URL 丢弃。

## 向量空间一致性守卫(正确性核心)

换嵌入模型 = 换向量空间:旧向量与新 query 的余弦不可比,混用的结果是检索永远低于
`SEARCH_MIN_SCORE(0.3)`,冷记忆**悄悄失效**而非报错。守卫:

- `VectorsFile` 增加可选 `embedder` 指纹(字符串,如 `local:`、`endpoint: profileId/model`);
  `createFileVectorStore(io, collection, fingerprint?)` 在 initialize 时比对:
  - 档案已有指纹且 ≠ 当前 → 重开空库(清 items)+ `console.warn`;
  - 档案无指纹(老版本存量)→ 保留,首次写入时补上(向后兼容,不激进重置)。
- 指纹由 `mem0Memory.ts` 在 init 时按当前 settings 计算,经第三参传入。

## fail-open 纪律(不变)

本地服务没起 / URL 写错 / 响应不合法 → init 探测失败 → 经历记忆整体停用(检索返回空、
写入记 false),Warm 滚动摘要照常,聊天链路零感知。设置页 `probeStatus()` 可见 error。

## 设置 UI(PrivacySettings「经历记忆」卡片)

- 「嵌入来源」选择:云端端点(缺省)/ 本地 llama.cpp。
- local 分支:服务地址输入框(占位 `http://127.0.0.1:8080/v1`)+ 模型名(选填)+
  启动命令提示 `llama-server -m <模型>.gguf --embedding --port 8080` 与模型体积参考。
- endpoint 分支:维持现有「嵌入档案 + 模型名」两字段。
- 来源/模型切换后旧向量不可用由指纹守卫兜底,卡片提示文案说明。
