# 聊天入口设计方案(单聊 / 群聊)

把「聊天」从设置能力升级为独立的用户功能入口:主窗控制栏 💬 打开聊天面板,
内部区分 **群聊**(多角色房间)与 **单聊**(1对1,每角色一间)。

## 1. 职责分离

- **聊天面板(本方案)**:负责「我要跟它聊」——会话列表、消息流、输入。
- **设置窗**:负责「它怎么聊」——模型绑定(AI 模型页·群聊角色绑定)、活跃度、
  群名/背景(聊天记录页)。设置窗的聊天记录页退役实际聊天(移除发送框),
  只做历史翻看与管理。

## 2. 会话模型与引擎

```text
ChatPanel(主窗 chat overlay,层级式:会话列表 → 单会话)
   │                    │
 群聊会话              单聊会话(每角色一间)
 group:main           direct:A / direct:B / direct:C
   └──────────┬─────────┘
   ChatSession 工厂(session/conversations.ts 注册表)
              │ GroupChatRuntime(群聊=全员房间;单聊=单角色房间)
              └→ actorPrompt(direct 直答形态)→ Memory → Expression → LLM
```

- **sessionId 约定**:`group:main` / `direct:<slot>`;chatlog.jsonl 单文件按
  sessionId 过滤读取(`listChatTurns(limit, sessionId?)`;无 sessionId 的旧
  条目/演出插话归群聊房间)。
- **direct 会话**(`session/directSession.ts`):
  - 单角色房间:runtime config override 只启用房主角色,其余 disabled(游标跟尾);
  - **面板模式呈现**:回复不弹舞台气泡、不朗读(presentTurn no-op、
    speakTracked 立即 ended),只由聊天面板按房间渲染;提交顺序/静止谓词不变;
  - **直答形态(无 decision 协议)**:prompt 无输出协议块/无群聊纪律
    (`actorPrompt` direct 形态),adapter `protocol:'plain'` 把模型原始文本
    经 `plainSpeakReaction` 直接包成内部 speak reaction(空文本退避、600 字
    钳位);router 的预算/去重/游标原样复用,worker maySpeak 恒真;
  - 历史:创建时按 sessionId 过滤 chatlog 尾部 60 条引导;
  - 网页模型会话键 `direct:<slot>:…` 与群聊键隔离(各自独立标签页)。
- **会话注册表**(`session/conversations.ts`):群聊会话由 App 装配后注册,
  单聊会话按角色惰性创建;清空聊天记录时一并 reset。

## 3. 聊天面板(chat/ChatPanel.tsx)

- 层级式两视图:**会话列表**(群聊行 + 三角色行,头像/最近一条/未读点)
  ⇄ **单会话**(← 返回,消息流 + 输入框,Enter 发送);
- 消息流 = chatlog 按房间过滤尾部 50 条,`useChatLogVersion` 驱动增量;
- 未读:面板关闭期间的新消息按 sessionId 记 localStorage 时间戳,列表显点;
- 📌固定:固定后点外部/Esc 不收起(App 的 overlay 收起豁免,同翻译面板);
- 硬纪律:面板含输入框 → 命中注册 `activatesWindow: true` + 进
  `interactivePanelsOpen`;根 ref 由 App 注册原生热区。

## 4. 桌面快捷入口

角色右键菜单(小哀/柯南/大肥鱼)首项「💬 和TA聊天」:打开聊天面板并直达该
角色单聊房间。不新增双击手势(避免与单戳/拖拽误触冲突)。

## 5. 已知限制(二期)

- 表达导演动作冷却与世界注记账本是全局单例,单聊/群聊并发共享节奏(不影响
  正确性,影响"新鲜感"),二期按房间分账;
- 主动聊天(proactiveScheduler/自发闲聊)仍走演出短聊通道,不进单聊房间;
- 语音闭环只接群聊房间;
- 设置里「单聊设置/群聊设置」的分 tab 展示待做(当前单聊复用群聊角色绑定的
  模型与活跃度配置)。
