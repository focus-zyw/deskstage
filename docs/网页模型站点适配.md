# 网页模型站点适配

网页版生成通道用系统 Edge 的独立 profile 打开站点标签页,经 CDP 注入脚本发送 prompt、
抓取回复。**站点知识的唯一事实源是 `src-tauri/src/webchat/sites.rs`**——调度器
(`webchat.rs`)只认 adapter 字段与方法,不出现 `if site` 分支;站点改版只改这一个文件。

## 当前站点

| id | 显示名 | 入口页 | 输入框 | 这条站点独有的坑 |
|---|---|---|---|---|
| `deepseek` | DeepSeek 网页版 | `chat.deepseek.com` | textarea / contenteditable | 圆形发送键启用晚于插入,填好后要补点一次 |
| `doubao` | 豆包网页版 | `www.doubao.com/chat/` | textarea / lexical contenteditable | 回复根节点是 `v_list_row`,与别的站点完全不同 |
| `qianwen` | 千问(通义)网页版 | `www.qianwen.com` | React 受控 contenteditable | 发送键只在**真实提交**后才启用,`insertText` 不触发提交 |
| `chatgpt` | ChatGPT 网页版 | `chatgpt.com` | Lexical contenteditable(`#prompt-textarea`) | 上千字的 `insertText` 会逐字建节点并冻死标签页,长 prompt 必须走粘贴 |
| `gemini` | Gemini 网页版 | `gemini.google.com/app` | Quill(`.ql-editor`) | 靠 `ql-blank` 类名认定"没编辑过",不摘掉就不启用发送键 |

`chatgpt` / `gemini` / `qianwen` 的选择器与交互策略移植自 `D:/web-tool` 的
`extension/content/{chatgpt,gemini,qianwen}.js` 以及它们的共享骨架 `runtime.js`
(`pasteReplace` / `fillContentEditable` / `settlePaste`)。

> **选择器是时点快照。** 三站移植后**尚未在真机上跑过**——本仓库只做了单元测试
> (脚本装配、占位符替换、站点 DOM 互不串味)与类型/构建校验。首次使用前请按设置页
> 「打开窗口 → 登录 → 查状态」走一遍;`查状态` 报"输入框未出现"就是该更新本表选择器了。

## adapter 字段

| 字段 | 作用 |
|---|---|
| `url` / `host` | 入口页;标签页归属判定(页面 URL **包含** `host` 即视为本站) |
| `composer_sels` | 输入框(顺序即优先级,取第一个可见的) |
| `send_button_sels` | 发送键;**为空或全禁用时退回 Enter** |
| `send_retry_sels` | 第一次点击没被吃掉(输入框没清空)时的兜底键 |
| `message_root_sels` | 助手回复根节点,取最后一个当"本回合的回复" |
| `markdown_body_sels` | 回复正文块;只读这些块,避开头像/工具栏等 chrome |
| `thinking_sels` | 思考过程节点,抓取前整块摘掉 |
| `stop_sels` | 生成中标记。停止键不一定带 `aria-label`(ChatGPT 是 `data-testid`、千问是 `data-is-streaming`、Gemini 是 `.stop-icon`) |
| `complete_sels` | 收尾标记。最后一个回复根里/之后找不到它 = 本回合仍在生成 |
| `fill` | `Standard`(textarea setter + `insertText`)或 `Paste`(合成粘贴,单次事务) |
| `clear_classes` | 填充前从输入框摘掉的类名(Gemini 的 `ql-blank`) |
| `beforeinput` | 填充前是否先派发 `beforeinput`(Quill 依赖) |
| `paste_if_send_disabled` | 填完发送键仍禁用时,select-all 后补一次合成粘贴 |

## 新增一个站点

四处都要改,**缺一处就会被清洗函数挡掉或探测不到**:

1. `src-tauri/src/webchat/sites.rs` —— 加一个 `SiteAdapter` 常量 + `adapter()` 里的分支,
   并把新 id 加进测试的 `ALL_SITES`(漏配分支会当场炸)。
2. `src/storage/configStore.ts` —— `WEBCHAT_SITE_IDS` 加 id(类型与两个清洗函数的白名单
   都由它派生)。
3. `src/engine/webchat.ts` —— `WEBCHAT_SITES` 加一条显示名。
4. `src/settings/settingsCatalog.tsx` —— 网页版生成那两条的 `keywords` 补上站点名,
   否则设置页搜索找不到。

## 排查

- **ask 稳定地跑满超时** → 先看该站点的 `complete_sels`:站点把这组按钮拿掉后,
  "本回合没结束"永远成立。这是 ChatGPT 侧"最近变慢"的第一嫌疑点。
- **报"提示词未能写入输入框"** → 输入框选择器过期,或填充策略不对(该走粘贴的站点
  用了 `insertText`)。填充判定只比可见字符(忽略换行与连续空白),富文本重排不会误判。
- **报"页面上找不到输入框"** → 多半是没登录(未登录站点通常不渲染输入框)。
- **回复抓回半截** → `message_root_sels` / `markdown_body_sels` 里混进了嵌套节点,
  或 `stop_sels` 没覆盖该站点的生成中标记。
