# 测试编写约定

> 本仓库 2026-09 起测试不再默认经 Vite 加载(全量回归因此从 10~20 分钟降到 ~18 秒)。
> 写新测试前先读这份约定;入口 `pnpm test` 会自动分流,但风格请按下面的来。

## 新测试怎么写(默认形态)

- 文件放 `tests/<主题>.test.mjs`,用 `node:test` + `node:assert/strict`。
- **不启动 Vite**。src 模块用原生动态 import(带 `.ts` 扩展名),放在 `before()` 里
  保持求值时机与测试断言解耦:

  ```js
  import assert from 'node:assert/strict'
  import { before, test } from 'node:test'

  let foo

  before(async () => {
    ;({ foo } = await import('../src/engine/foo.ts'))
  })
  ```

- 依赖注入优先,不碰网络与磁盘;localStorage 用内存桩(Map 实现),用完
  `delete globalThis.localStorage`。
- `import.meta.env` 无需关心:`tests/_envHook.mjs` 会对引用它的模块注入 Vite 默认值
  (`DEV:false`、`BASE_URL:'/'`),URL 拼接产物与 Vite 一致。
- TSX/React 组件直接 import 即可,JSX 由 tsx 按 `tsconfig.app.json` 的 `react-jsx` 处理。
- node --test 每个文件跑在独立进程里,不要依赖跨文件的模块单例状态。

## 何时才允许 vite 自举

只有需要 mock `@tauri-apps/*`(或整个 react/jsx-runtime)时:仿照
`tests/webchatHub.test.mjs`,在文件内自起 `createServer` + 内联插件,并在文件头加注释
说明保留原因。运行器(`scripts/run-tests.mjs`)按文件是否含 `from 'vite'` 自动分流到
vite mock 组;两种风格都能跑,但默认请用直载形态。

## 入口

| 命令 | 范围 | 耗时 |
| --- | --- | --- |
| `pnpm test` | 全量(98 直载 + 9 vite mock) | ~18s |
| `pnpm test:fast` | 14 个纯逻辑快测 | ~5s |
| `node --import ./tests/_tsxSetup.mjs --test tests/xxx.test.mjs` | 单文件 | <1s |

## 纪律

- 别把 vite 样板复制进新文件;也别动 9 个 mock 文件里的 createServer/插件块
  (那是在删 mock,会以"真实 Tauri API 裸奔"的方式坏掉)。
- 跑全量若见失败,先单独重跑该文件确认,再怀疑转换/环境;
  `tests/_tsxSetup.mjs` 与 `tests/_envHook.mjs` 是所有直载文件的前置依赖,改名需同步
  `scripts/run-tests.mjs` 与 `package.json`。
