# 自发闲聊记忆闭环设计方案

> 审计结论(docs 会话记录):自发闲聊(greeting/spontaneous)台词播完即蒸发——
> `playShortChat` 不带 `opts.history` 不落演出史,不走 chatlog,不进 story 蒸馏;
> 后续自由聊天的全部上下文源(journal 房间历史 / chatlog→warm 摘要 / 用户事实 /
> story 老梗)都看不到它。对方项目(Re-Dreaming)的"互聊片段写进各自记忆、
> 以后真能聊起"闭环,我们没有等价物。本方案补上这一环。

## 目标

角色自发说过的话,成为后续自由聊天可见的上下文——用户聊起相关话题时,角色
"真能记起自己说过什么"。同时闲聊记录出现在聊天面板(群聊 tab),桌面更有"他们
自己在生活"的实感(对方项目同款体验,审计时已认定为 feature 而非打扰)。

## 两条 sink(与普通聊天消息同构)

普通角色回复天生进两个存储:actors **journal**(投递语义,后续批次/上下文的
事实源)与 **chatlog**(面板渲染 + 生命周期 warm 摘要源)。自发闲聊补齐同款:

1. **journal 环境注入(核心)**:新增 `RoomRouter.injectAmbient(lines)`——台词按
   角色作者写进 journal,然后**全员游标(ackedThrough/deliveredThrough)推到尾部**。
   效果:不是"未读"(不触发任何 worker 唤醒/限流/批次),但此后每个批次的
   `recentContext`(readTail)与表达导演的 `recent` 都能看到它们——这是
   "以后真能聊起"的直接机制,且不依赖任何开关(生命周期摘要默认关也生效)。
2. **chatlog 镜像**:`appendChatTurns(sessionId=group:main)`——面板可见 +
   contextLifecycle 观察后 warm 滚动摘要自动携带(开启生命周期时与 journal
   双通道印证,与普通消息的重复注入现状一致)。
3. **observeTurn**:镜像后按既有门控(contextLifecycle 开)逐条观察,折算进
   warm;who 直接用角色槽位(LifecycleTurn.who 是 string,天然支持)。

## 安全闸(注入的并发纪律)

环境消息只准在"全员静止点"入场,否则两个真实风险:

- **吞真未读**:游标推尾会让尚未被某角色读过的用户消息被跳过;
- **游标回退**:在飞批次的 ACK 会无条件写 `ackedThrough = batch.throughSeq`,
  把游标拉回环境消息之前(在飞批量反而变回未读)。

因此 `injectAmbient` 前置拒绝:任何非 disabled 角色存在**未读**
(`unreadCountOf > 0`)或**在飞批次**(`deliveredThrough > ackedThrough`)时整体
放弃(返回 false,聊天记录镜像照常)。自发闲聊由主动调度器保证在空闲时发生,
该闸几乎不触发;触发了也只退回现状(台词不留痕),绝不产生投递事故。
另外:paused(用户停止)时拒绝;causalRootId 取自身 id、不建链、不进预算。

## 范围

- **收录**:greeting(开机问候)与 spontaneous(自发闲聊)——它们是"角色自己
  说话"的同一类,且都经 playShortChat 播出(上报点收在那里,一处覆盖两通道)。
- **不收录**:久坐提醒(是系统对用户的提醒,落面板成噪音)、备忘讨论(注释
  明确"不写历史")、自动重放(本就是历史集重演)、C 团宠(不受 short chat 影响)。
- **不做的**:演出史(演出史保持"策展过的剧",闲聊走 chatlog)、story 蒸馏
  源扩展(可评估的后续,不在本方案)、直接房间(单聊没有"他们自己聊"语义)。
