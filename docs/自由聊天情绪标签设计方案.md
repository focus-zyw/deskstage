# 自由聊天情绪标签设计方案

> 调研来源:Re-Dreaming_Angels_DesktopPet 的 `<mood:X>` 协议(见会话调研记录)。
> 结论:本项目"怎么说"(表达导演)与"跨句情绪惯性"(moodState)都已存在且更强,
> 唯独缺"这一句回复是什么情绪 → 立绘表情联动"——自由聊天回复目前恒为 `talk` 姿势
> (`App.tsx` presentTurn 硬编码)。本方案借对方的 in-band 标签协议补上这一环,
> 并把标签喂回 moodState 形成对方没有的闭环。

## 现状缺口

- 群聊/语音房间(actors schema 协议):`reply.action` 字段已存在但被指导
  "一般填 talk",提交时被丢弃,呈现恒 `talk`。
- 单聊面板房间(plain 直答):纯文本无协议,呈现通道本身 no-op(设计上面板模式
  零气泡零 TTS),角色在桌面上对聊天内容零反应。
- moodState(valence/energy)只由剧情蒸馏与戳一戳更新,聊天回复不产生余波。

## 方案总览

情绪词表**对齐自家立绘动作词表**(spriteSets actions),不引入对方 7 态中没有资产的
proud/tired:

| 标签 | 动作 | 情绪增量(dValence, dEnergy) |
| --- | --- | --- |
| happy | happy | +0.4, +0.2 |
| laugh | laugh | +0.6, +0.4 |
| surprise | surprise | 0, +0.4 |
| sad | sad | −0.6, −0.3 |
| angry | angry | −0.8, +0.4 |
| shy | shy | −0.1, −0.2 |
| sleepy | sleepy | −0.1, −0.6 |

两条通道各用一种载体,呈现侧统一查同一张表:

- **plain 直答(单聊面板)**:in-band 标签 `<mood:X>` 追加在回复末尾同一行;
  adapter 层 `plainSpeakReaction` 解析后剥除、映射为 `reply.action`。
- **schema 群聊**:不引入 in-band 标签——既有 `reply.action` 字段就是载体,
  只把协议指导从"一般填 talk"放宽为按情绪词表选(平淡仍 talk)。
  `parseActorReaction` 顺手剥除可能混入 text 的标签形残渣(双保险)。

## 防线三层(照搬对方教训)

1. **生成端规则**:plain 直答纪律块(两种形态都注入)带标签规则与示例;
   群聊协议行改词表。措辞必须给"情绪平淡就不加"的出口,防标签通胀成噪声。
2. **入口剥除**:adapter 层解析时剥除(落盘 journal、质量闸、TTS、诊断全干净);
   剥除**先于** 80/600 字截断,标签不占台词预算、质量闸 over-length 不误报。
3. **显示层兜底**:useActorPresenter 的 say/showTalk 统一剥标签——历史/回放/
   其他通道漏网文本渲染前最后一道闸(我们的消息落 jsonl、进诊断、进回放,泄漏面更大)。

解析容错:主格式 `<mood:X>`;笔误形式 `<X>`(仅白名单词,非白名单的 `<>` 不吞);
未知 `<mood:proud>` 剥除但不映射。多次出现取最后一个合法值。

## 闭环节选(对方没有的一步)

onCommit 对带情绪动作的回复把增量写入 moodState(走既有 `applyMoodDeltas`,
单笔钳 MAX_EVENT_DELTA,小时级惰性衰减):连聊几句被逗乐 → 待机染色真的挂笑意、
下一轮 prompt 的心情余波自动接上。无标签 = 无增量,不产生漂移。

## 呈现语义

- 群聊/语音房间:presentTurn 透传 action → presenterSay 查表切动作
  (未识别回落 `talk`,与现状一致)。
- 单聊面板房间:**保持零气泡零 TTS 不变**,新增仅"动作反应"——host.presentMood
  驱动舞台姿势一拍(~2.6s)后经既有放松链回 idle;不识别(talk)不动作,
  桌面保持安静。这是对"面板模式不抢戏"决策的最小例外:只有姿势、无声音无文字。

## 不做的事

- 不给演出/剧本通道加标签(结构化 JSON 逐句 action 已是权威)。
- 不动 legacy 引擎路径(呈现兜底 strip 已覆盖其显示面)。
- 不引入对方 proud/tired 等无资产情绪,不照抄 7 态表。
- 不做"标签→气泡高亮"等额外呈现,先验证动作联动本身。
