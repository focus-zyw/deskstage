# 生活线系统设计方案(近期经历滚动层;设计定稿,未实施)

> 核心不变量:**事件必须留下可回收的痕迹,否则不出场;生活默认无事发生,有戏也只是小事。**

为角色引入"正在经历的生活":每个角色维护 2~3 条进行中的**生活线**(一段有名字实体的小事,
如"常客老陈的准点早餐""B 手里那个改了三版的需求"),由 LLM 周期性推进一小步
(有时推进 = 无事发生),线程当前态注入日常模式 prompt 与群聊上下文,命名实体进入旧梗候选。

动机(见 RimTalk 对照结论):对话平淡的根源不是模型不会写,而是**角色没有正在经历的生活**——
素材供给缺口。本系统是"全量世界模拟器"的 20% 复杂度版本,拿走 80% 收益。
最大赢家不是主演出而是**群聊**:A/B/C 目前只共享房间聊天记录,没有共同生活;
一条共享的"我们都经历过的破事"就是多角色内部梗的源源素材。

**与既有系统的关系(共用底座,不新建骨架)**:事件 → 持久状态 → 台词 → 回收的闭环里,
记忆 V3 做事实骨干、mood/bond 做后果(P3)、story.json gags/threads 做可回收素材、
话题系统吃事件当种子(P3);怪癖系统的"事件→行为模式→怪癖"通路设计已就绪——
生活线上线那天,结晶(P2)直接获得高质量喂入口。

## 1. 目标与非目标

**目标**
- A/B/C 各自 2~3 条活跃生活线 + 全局 1~2 条**共同线**(三人共享的破事),持久化、跨重启稳定。
- 周期性推进:每 N 集结算一次,每次恰推进一条线一小步,或判定"无事发生"。
- 注入:日常模式 prompt(个人线 + 共同线)、群聊 fullContext 轮(共同线)。
- 线程命名实体 + 标题登记为导演旧梗候选的**第三只读源**(L-P2)。
- 全程实验开关,默认关。

**非目标**
- 不动相声/喜剧通道(包袱结构已很强,塞剧情线稀释节拍)。
- 不做全量世界模拟、不做事件因果图、不做"谁知道什么"的视角管理。
- 不在群聊房间公示事件(生活线是氛围不是演出,与怪癖获得的"公示"相反)。
- 不接 mood/bond 偏移、不接话题导演(P3 评估)。
- 悲剧/重大戏剧转折不做——事件是小事级,见强度纪律。

## 2. 数据模型

```ts
interface LifeThread {
  id: string
  scope: 'A' | 'B' | 'C' | 'shared'   // 个人线归属角色;shared = 三人共同线
  title: string        // 一句话,必须含命名实体:"常客老陈的准点早餐"
  state: string        // 当前态一句话:"老陈最近改点下午来了,带着他家猫"
  openedEp: number
  lastBumpEp: number
  bumps: number        // 推进次数(idle 不计)
  retired: boolean     // 已收尾:不再注入,保留供旧梗回收
}

interface LifeShape {
  version: 1
  threads: LifeThread[]
}
```

- 存储:独立 `data/life.json`(moodStore/quirksStore 同款:fileLock + localStorage 降级 + 订阅);
  写锁键 `'life'`,与 `'quirks'` 不冲突。集数计数**复用 quirks store 的 episode**
  (`bumpEpisode` 已在 `notePerformanceEpisode` 里),本 store 只存 openedEp/lastBumpEp 数值。
- 配额:个人 scope 活跃(未 retired)≤ `MAX_ACTIVE_PER_SCOPE = 3`;shared ≤ `MAX_SHARED = 2`;
  retired 保留但全库上限 30 条,超出淘汰最旧(retired 线是旧梗素材,不是活跃状态)。

## 3. 推进协议(结算器)

### 3.1 触发

`notePerformanceEpisode()` 扩展:每集集数 +1 后,若 `episode % SETTLE_EVERY === 0`
(SETTLE_EVERY 默认 5)则触发一次结算——**每次只推进一个 scope**(上一次结算时间最久的那个:
个人三 scope 与 shared 轮转)。fire-and-forget,失败静默 + 全局冷却 5 分钟(同怪癖);
设置页"推进一步"按钮带 force 绕过冷却。生成走 API 单次 JSON 通道(同怪癖)。

### 3.2 prompt 模板(定稿)

```text
你在为桌面情景剧维护角色的「生活线」：每条线是一段进行中的小事，有名字的实体，会小步推进。

【角色设定】
{persona}

【该角色的怪癖】（事件可以擦到怪癖，但不要围绕怪癖编剧情）
{quirkLines 或"(无)"}

【生活线现状】
{threads:- [id] 标题 ｜ 当前态 ｜ 开线于第X集 ｜ 已推进Y次}

【近期素材】（按可信度排序，优先从中取材，不要凭空造大事件）
{material:①已采纳的剧情蒸馏产物(gags/threads) ②引发了接话/观众互动的对话片段 ③一般概要}

推进规则：
1. 恰好选一条线推进一小步：一句话的新事件或状态变化。推进必须小——下一个场景、一次偶遇、
   一个变化的前兆，不是高潮。
2. 约 1/3 的概率应当输出 idle（无事发生/只是想起来）。生活不是每天都有戏。
3. 事件是小事级：不出现重伤/分手/离职/破产/死亡级别的转折；风味可以离谱，后果必须平常。
4. 线里必须有名字的实体（人名/店名/项目代号/宠物名）；新开线同理，实体名要普通可信。
5. 某条线已自然讲完或长期无戏时，可以 retire 它；若该 scope 配额有空，可同时开一条新线，
   新线必须从【近期素材】取材。
6. 不破坏角色人设；事件符合角色的日常舞台；与人设基调冲突的"戏"不做。

只输出 JSON，不要解释，不要 Markdown：
{"threadId":"...","action":"advance|idle|retire","event":"一句话新事件(advance 必填)",
 "newState":"推进后该线的当前态一句话(advance/retire 必填)",
 "newThread":{"title":"...","state":"..."}(仅 retire 且配额有空时提供,否则省略)}
```

- **idle 出口**(对应怪癖 skip):`action:"idle"` 是正常产出,不算失败不进冷却——
  低质素材期生活线产出"无事发生"是设计行为。
- **素材源优先级**(白嫖结晶设计的源序):①story.json 已采纳 gags/threads
  (已过质量闸+开播采纳)> ②chatlog 中引发了接话/观众互动的片段(replyTo/互动记录现成)>
  ③一般概要。P1 实现允许只接③,①②在接入时标明层级。
- 解析容错分档同怪癖:threadId/action/newState 严格,event 长度截断,坏 JSON 静默放弃。

## 4. 强度纪律(生活线版)

> 事件是"正常生活的小波澜",不是剧情;观众应该觉得"这人日子过得挺有意思",
> 而不是"这角色怎么天天出事"。

1. 一集一事:每次结算至多一条线动一步;其余线原样。
2. 静止合法:idle 是三种等产出口之一;连续两次结算全 idle 不算异常。
3. 小事级:不夺走任何"正常生活照常进行"的东西(怪癖强度纪律第 1/4 条同源)。
4. 命名实体强制:无线名不成线——"一个常客"不合格,"常客老陈"合格。
5. 可复现:推进优先让已有命名实体回归(老陈第二次来),而不是不停新增实体;
   实体回归才是"世界"的体感来源。
6. 不肥皂:禁止为有趣升级强度;连续两线都出现"冲突类"事件时,下一次结算必须 idle 或温情向。

## 5. 运行时注入

### 5.1 日常模式(主通道)

`promptBuilder` 在怪癖块之后追加生活块(同 `renderQuirkBlock` 模式,纯函数):

```text
近期生活(已发生的事,可以自然提起或延续,不要播报,无事不提):
- {name}:{state}
- (共同){state}
```

使用纪律一句:"这些是背景,不是本集任务;可以自然引用,不要求每集都提"——
与怪癖"重力不是任务"同一哲学,但只要一句,不需要五句(生活线的误用风险低于怪癖)。

### 5.2 群聊(L-P2)

`ChatSession.prepareExtras` 在 factsLine 旁新增 `lifeLine`(仅 shared 线;个人线不进群聊,
那是各角色自己的事),随 fullContext 轮进入 `PromptBuildInput`(新增可选字段)。
网页增量轮不带(与纪律块同一限制),站点会话内自然延续。

### 5.3 旧梗第三源(L-P2)

生活线 title + state 中的命名实体,随 story.json 旧梗、怪癖 cause 之后登记为导演 callback
的第三只读预选源(同一"不写注入冷却、不烧主演出额度"模式);线程 bumps/lastBumpEp 做冷却记账。

## 6. UI

设置 → 角色人设 页,怪癖卡之后新增**「角色生活」卡**(常驻显示 + 卡内启用开关,同怪癖卡模式):
- 按分组列出 甲/乙/丙/共同 的活跃线:title + state + 开线集数 + 推进次数;
- 每线操作:**推进一步**(force 结算该 scope)/ **收尾**(retire,腾出配额);
- 收尾线折叠为"已结束(可被旧梗回收)"计数,不展开列表;
- 总开关 `lifeSystem`,隐私页与卡内双开关同写一字段(同怪癖双开关惯例),默认关。

## 7. 配置开关

configStore 增 `lifeSystem: boolean`,expressionV2/quirkSystem 同款三处规范改法,默认关。

## 8. 测试计划

| 组 | 用例 |
|---|---|
| 存储 | 往返持久化;各 scope 活跃配额;retired 保留与 30 条淘汰;写锁互不干扰 quirks |
| 结算 | SETTLE_EVERY 触发一次;scope 轮转选最久未推进;idle 不进失败冷却;retire+开线配额判定 |
| 解析 | 三 action 校验;advance 缺 event 拒收;retire 缺 newState 拒收;坏 JSON 静默 |
| 注入 | 生活块格式(个人+共同前缀);关闭/无线空串;开关关 prompt 逐字节回归 |
| 群聊 | lifeLine 仅 shared 且仅 fullContext 轮;开关关不注入 |
| 纪律 | prompt 含强度纪律六条关键句(静止合法/命名实体/小事级/不肥皂) |

## 9. 分阶段

- **L-P1**:存储 + 结算器 + 日常模式注入 + UI 卡 + 开关(素材源先只接③一般概要)。
- **L-P2**:群聊 shared lifeLine(prepareExtras 管线)+ 旧梗第三源(导演预选 + 冷却记账)
  + 素材源接①②(蒸馏产物/互动信号)。
- **L-P3**:结晶喂入口(P2 结晶落地时,生活线事件直接作为高质量源)、mood/bond 偏移联动、
  话题导演吃事件当 hook。

## 10. 开放问题

1. SETTLE_EVERY=5 与每 scope 线数(3/2)为拍脑袋初值,实测调。
2. 素材③"一般概要"的产物形态:chatlog 尾部裁剪 vs 复用现有摘要产物(P1 实现时定,倾向裁剪)。
3. 生活块注入是否参与怪癖那样的"轮换子集"(线多后同问题),先全量注入,线满再议。
4. shared 线与个人线冲突时(共同线说 A 出差、A 个人线说 A 在店里)以谁为准:倾向 shared 让位
   个人线(个人线更贴人设),结算 prompt 加一句消歧,实测再定。

## 11. 与 P2 的排序约定

本系统排在怪癖 P2(结晶/导演接线/冷却消费)之后启动,共用底座
(API 单查通道、fire-and-forget 编排、存储模式、注入纯函数模式、UI 卡模式均已就位,
增量工程量显著小于怪癖 P1)。结晶落地时,生活线事件按"已采纳蒸馏产物"同级
进入结晶源优先级①层——世界层上线之日,即结晶高质量喂入口通流之时。
