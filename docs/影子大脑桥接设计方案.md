# 影子大脑桥接(Shadow Brain + AgentBridge)设计方案

> 动机:让外部编码 Agent「进入桌宠运行现场」——观察现场、诊断、模拟决策,把
> 「主动发言的感觉」逐渐变成可实现的规则。定位不是「Agent 接管桌宠」,而是
> **Developer Brain / Shadow Brain**:开发期工具,正式版整体编译剔除。

## 目标与范围

- **做什么**:应用内开一个仅监听 `127.0.0.1` 的本地桥,外部 Agent(运行中的编码
  Agent / 自动化脚本)用 curl 即可:读运行现场快照(BrainInput)→ 提交决策
  (BrainDecision)。三种模式:
  - **shadow(影子对照)**:外部决策只落盘不执行,与本地大脑在同一时刻的评估
    配对存档——几百条这样的记录,比坐在那里设计「主动发言公式」有价值得多;
  - **speak(现场指挥)**:Agent 随时 `POST /brain/speak` 让桌宠立刻说指定台词
    (复用 playShortChat 通道,台词/表情/TTS/记忆闭环一概复用);
  - **takeover(接管)**:调度器走到候选决策时刻,经 long-poll 问外部 Agent,
    预算内(默认 6s)不回就回落本地大脑,绝不卡桌宠;迟到的决策仍落影子。
- **不做什么(v1)**:
  - moodState 的 VAD 化迁移(存储 schema/提示词/衰减全链路)——只做 VAD 协议层
    与映射,迁移是后续独立工程(见「终态路线图」);
  - intimacy/trust/fatigue 维度、Relationship 模型——同上,路线图占位;
  - WebSocket——编码 Agent 是 curl 原生的,HTTP 轮询 + long-poll 已覆盖全部场景;
  - 正式版(release)打包桥——`#[cfg(debug_assertions)]` 整体剔除。

## 总体架构

```
外部编码 Agent(curl / 自动化)
        │  HTTP 127.0.0.1:port + X-Bridge-Token
        ▼
Rust bridge.rs(纯传输,#[cfg(debug_assertions)])
  手写极小 HTTP/1.1 · 输入环 · 接管请求 oneshot waiter · token 校验
        │  tauri 命令 bridge_push_input / 事件 bridge-decision / bridge-speak
        ▼
TS src/brain/(语义层,纯函数可测)
  vad.ts · types.ts(协议清洗)· snapshot.ts(现场快照聚合)· shadowStore.ts(JSONL 落盘)
        │                                    │
        ▼                                    ▼
proactiveScheduler.observe(LocalEvaluation)   playShortChat(lines) 执行通道
(全应用唯一"该不该主动说话"决策点)              (台词/表情/TTS/noteAmbient 复用)
```

分层原则:**Rust 只做传输,语义全在 TS**——快照内容、决策校验、配对落盘、执行
都走既有 TS 模块;TS↔桥只经 tauri 命令/事件,不经 WebView fetch(CSP 零改动)。

## 传输桥(Rust)

- `tokio::net::TcpListener`(net feature 已开,**零新依赖**)+ 手写极小 HTTP/1.1:
  只支持 GET/POST、按 Content-Length 读体、`Connection: close` 单请求单连接、
  拒绝 chunked;回环测试先例:`webchat.rs`(真实 TCP + WS accept)、
  `endpoint_proxy.rs`(真实 TCP 服务器)。
- 首启随机端口 + 随机 token,持久化 `appData/data/bridge.json`
  (`{port, token, startedAt}`),Agent 侧据此发现端口;token 不匹配一律 401。
- `BridgeState`(managed,仿 `endpoint_proxy::ProxyState`):
  - `inputs: VecDeque<BrainInputJson>` 输入环(cap 120,约 30 分钟 tick 粒度);
  - `waiter: Option<oneshot::Sender<RequestJson>>` 接管请求长轮询挂号;
  - `counts` 请求/决策计数(设置页展示)。

### 端点

| 方法/路径 | 语义 |
| --- | --- |
| `GET /brain/status` | 模式、端口、输入环长度、输入/决策计数、启动时刻 |
| `GET /brain/inputs?last=N` | 最近 N 条 BrainInput(内存环,永远新鲜) |
| `POST /brain/decisions` | 影子批量应答:`{decisions:[BrainDecision]}`,逐条校验 inputId 已知,落盘不执行 |
| `GET /brain/requests?waitMs=25000` | 接管长轮询:挂号等待,30s 无请求则回 `{requests:[]}` |
| `POST /brain/decision` | 接管应答:`{requestId, ...BrainDecision}`,完成 waiter;超预算的迟到应答转影子落盘 |
| `POST /brain/speak` | 现场指挥:`{lines:[{speaker,text,action}...]}` 或 `{text,action}`,受勿扰/全屏/角色隐藏闸门约束 |

## 协议(核心形状)

```jsonc
// BrainInput:一次「决策时刻」的运行现场快照。每次 tick(15s)推入 Rust 环;
// 心跳(默认 5min)+ 每次真实决策时刻,额外落 inputs.jsonl 存档。
{
  "inputId": "brin_0173", "ts": 1758100000000,
  "tick": { "idleForMs": 152000, "quotaUsed": 2, "quotaCap": 6, "sinceLastSpontMs": 900000 },
  "world": { "foreground": "editor", "processName": "zcode.exe",
             "activeWindowTitle": null,          // 仅用户已开窗口标题采集时携带(脱敏闸)
             "fullscreen": false, "idleMinutes": 0, "audioPlaying": true, "mediaName": "…" },
  "mood": { "A": { "vad": { "v": 0.4, "a": 0.3, "d": 0.0 }, "cause": "…" } },
  "memory": { "promptFacts": ["…"] },            // 与 generateShortChat 同源(prepareTurnMemory n=3)
  "recent": { "lastLines": ["…"] },              // chatlog 尾部 6 句,单句截断
  "interactions": { "dismissSpontaneous": 1, "dismissBreak": 0, "interrupts": 2, "pokes": 5 },
  "local": { "candidate": "spontaneous", "fired": false, "decline": "chance",
             "reasons": ["掷点未中(SPONT_CHANCE=0.4)"] }   // 本地大脑同一时刻的评估——配对的锚
}

// BrainDecision:外部 Agent 对某 inputId 的裁决
{
  "inputId": "brin_0173", "decision": "speak",    // speak | listen
  "reason": ["用户持续编码超过30分钟", "刚从失败状态转为成功", "过去15分钟桌宠未主动发言"],
  "memoryUsed": ["debug_session_104"],            // 引用 promptFacts 内容或自由 id,仅落 trace
  "expression": { "vad": { "v": 0.72, "a": 0.68, "d": 0.55 }, "label": "cheerful" },
  "lines": [ { "speaker": "A", "text": "…", "action": "happy" } ]   // speak/接管时给,takeover 无 lines 也可
}
```

清洗规则(TS 单源 `sanitizeBrainDecision`):字段白名单、`reason[]` 每条截 80 字
最多 6 条、`memoryUsed[]` 每条截 40 字最多 6 条、VAD 钳 -1..1、`lines` 每句截
200 字最多 4 句、`action` 必须在 VALID_ACTIONS 词表内否则丢弃、`decision` 枚举外
整条拒绝。未知 inputId 拒绝(防 Agent 基于过期现场发言)。

## VAD 表达层与终态路线图

决策协议的 `expression` 用**连续 VAD**(-1..1):v=valence(愉悦度)、a=arousal
(唤醒度)、d=dominance(支配度)。不要反过来只存离散标签——离散标签后面做渐变
很难;连续值内部保存,对 LLM/UI 映射标签:

```
V= 0.72 A= 0.68 D= 0.55 → cheerful   (vadToLabel,调试/Trace 展示用)
V=-0.55 A= 0.75 D= 0.62 → annoyed
V=-0.45 A= 0.18 D= 0.30 → gloomy
```

首期三件纯函数(`src/brain/vad.ts`):`vadToLabel()`(标签映射,调试界面/Trace 用)、
`vadToAction()`(落到既有 VALID_ACTIONS 词表供本地执行)、`moodToVad()`(把现有
moodState 的 valence/energy 投影成 VAD:v=valence/3,a 由 energy 归一,d 暂记 0
——本地暂无支配度信号,投影是单向有损的,文档即接口)。

**终态路线图**(本期不做,占位):

```
Character State
Mood                 Relationship
────                 ────────────
Valence(A)           Intimacy
Arousal              Trust(后加)
Dominance
Fatigue
    │
    └────────┐
             ↓
      Expression Director        ← src/expression 现有 ExpressionDirector 的进化方向
             ↓
      Energy / Humor / Initiative / Verbosity
             ↓
      Text / Face / Action
```

VAD 描述「她现在是什么感觉」,energy/humor 描述「她准备怎么表现」,intimacy 描述
「她和你是什么关系」。落地次序:① 本期 VAD 协议层;② moodState 存储迁移到
VAD+Fatigue(schema v4 + 衰减 + quantizeMood 重写);③ Relationship 独立账本;
④ ExpressionDirector 扩维。

## 调度器挂点(LocalEvaluation)

`proactiveScheduler` 是全应用唯一「现在该不该主动说话」决策点,但理由隐式在控制
流里。挂两处(纯逻辑小重构,既有测试必须原样通过):

- `SchedulerDeps` 加**可选** `observe?(e: LocalEvaluation)`:每个 tick 结束前回一次
  `{ blocked: 'gate'|'quota'|null, candidate: 'break'|'replay'|'spontaneous'|'none',
     fired: boolean, decline: 'cooldown'|'chance'|'quietHours'|'stretch'|'disabled'|null,
     idleForMs, quotaUsed }`——理由显式化,这本身就是「知道主动系统哪里太保守」的数据源;
- 新增导出 `schedulerTiming()`:只读快照 `{ allowedSince, lastActivityAt, lastSpontAttempt,
  lastSpontSuccess, lastReplayAt, lastBreakAt, quotaCount }`,供 snapshot.ts 聚合。

## 执行路径(复用,不新增演出通道)

- **speak / takeover 的台词执行**:`playShortChat(lines)`(usePerformanceDirector)——
  播前 setPose、逐句气泡+表情+TTS、`noteAmbient` 记忆闭环(chatlog 镜像 + journal
  环境注入)全部现成;台词由 Agent 给定,不再过 LLM。
- **闸门**:speak/takeover 播出前过 `getCaps()`(勿扰/面板/角色隐藏)与
  `isFullscreenApp()`;被闸时 speak 返回 409 语义、takeover 直接回落本地
  (本地同闸,表现为本 tick 什么都不发生)。
- **配额**:指挥播出计入调度器配额(`noteSpontaneous` + recordQuota 同语义),
  防止 Agent 把配额刷爆后本地大脑失声;takeover 播出与本地占用同一记账路径。

## 落盘与诊断

- `data/shadow-brain/inputs.jsonl` / `decisions.jsonl`:照抄 chatlog 模式
  (`withFileLock` 写锁 + 尾部裁剪 5000 行);decisions 记录自带提交时刻的
  `localAtDecision`(从环里取该 inputId 的 local 评估)——离线 join 零成本。
- diag 最小事件 `brain_decision`(对标 `memory_selection`:白名单标量字段,
  level basic;理由正文只落 JSONL,不进 diag,绕开脱敏面);`DiagSource` 增
  `'proactive'`。
- 「比较分析」不在应用内做:Agent 直接读 JSONL(或经 GET 端点)自行分析——
  这正是「让 Agent 进入现场」的本意。

## 配置与设置 UI

- `AppConfig.shadowBrain = { enabled: false, mode: 'off'|'shadow'|'takeover',
  port: 0(0=随机), heartbeatMs: 300000, takeoverBudgetMs: 6000 }`,三件套
  接口 + DEFAULT_CONFIG + FIELD_SANITIZERS(mode 枚举钳制、数值范围钳制)。
- 设置窗「链路诊断」dev 分页新卡「影子大脑(Shadow Brain)」:模式三档、端口与
  token 展示(点击复制)、输入/决策计数(30s 轮询,既有先例)、清空存档按钮;
  `import.meta.env.DEV` 为 false 时整卡隐藏(release 无桥,配置字段无害)。

## 安全与隐私

- 仅绑定 `127.0.0.1`;token 必配(首启随机生成);全部端点验 token,不匹配 401。
- `activeWindowTitle` 只有在用户已开「窗口标题采集」(contextSense.windowTitle)
  时才进快照——沿用既有授权闸,不新增隐私面。
- 快照含记忆事实与近期台词,文档明示:这是**本机开发工具**,发给的是本机上的
  开发 Agent;默认关闭,开启即视为知情。
- release 构建桥整体 `#[cfg(debug_assertions)]` 剔除,命令注册与 TS 装配双重
  判 `import.meta.env.DEV` + 配置开关。
