# AI 链路诊断与会话回放 设计方案

开发者面板(设置窗 → 数据管理 → 链路诊断),记录一次交互的完整链路:

```
用户输入 → 模型选择(API/网页) → prompt 与上下文 → 首 Token 延迟
        → TTS 分段与耗时 → 动作触发 → 记忆写入
```

目标:快速回答五个问题——

| 问题 | 面板上的证据 |
|---|---|
| 为什么这次没有说话? | `outcome` + `tts_segment` 的 outcome/reason(dnd/开关/被压制/未配置/取消)+ `asr_result`(空识别独立成会话) |
| 为什么走了网页版回退? | `fallback` 事件链(webchat→api / stream→整段 / turnBatch→单句)+ `webchat_stages` CDP 阶段轨迹 |
| 为什么角色记住了错误事实? | `memory_selection`(注入了哪些 id/落选原因)+ `memory_write`(候选数/新 id/被替代 id/拒绝数),点 id 实时解析现状 |
| 为什么取消后仍然播放语音? | `cancel_requested` + `tts_stopped`(停声时在播状态/epoch)+ 取消后 `audibleAt` 晚于取消时刻的段 → `cancelLeak` 章;`stop-noop` 段(epoch 不匹配停声失效) |
| 是网络问题、CDP 问题还是模型问题? | `llm_finished.errorKind`(timeout/network/http/parse/empty/cdp)+ CDP 阶段轨迹(edge_ready 慢=环境,first_text 慢=站点/模型,各阶段正常但超时=模型) |

## 三档隐私模型(核心设计)

密钥/Cookie/音频/截图/二进制任何档位都不进入诊断。

| 档位 | 触发 | 正文 |
|---|---|---|
| ① 默认诊断 | 常开 | **零可读正文**。只有长度/语言/来源/会话盐哈希/句数/耗时/memoryId/决策码/错误分类 |
| ② 临时详细诊断 | 手动:「捕获下一次交互」或「开启 10 分钟」,重启自动关闭 | 经 `redactText()` 的脱敏正文(输入≤500/回复≤1000 字)+ 实体掩码([USER_NAME]/[PHONE]/[IDENTITY_NUMBER]/[EMAIL]/[BANK_CARD]/[LOCAL_PATH]/[HEALTH_INFO]/[PRIVATE_ENDPOINT]…);可显式选「含原文」(仍强制密钥扫描) |
| ③ 显式导出 | 导出按钮,预览清单 + 默认不含文本 | 导出为唯一出口;勾选含文本时明确提示外发风险 |

保留策略:环仅内存(60 会话/单会话 400 事件/详情会话 ≤20),不落盘,重启即清。

脱敏四层防线(`src/diag/redact.ts`):
1. 架构层:诊断接口**只有类型化白名单事件**,没有 secret 字段可填,**不提供通用 trace.log(anyObject)**;
2. 精确值替换:业务持密处 `registerSecretValue()`(TTS/ASR 已接),出现即整体替换;
3. 已知格式:Bearer / sk- / Cookie 头 / sessdata / URL 凭证查询参数;
4. 高熵字符串兜底。

记忆诊断默认只记 id 与决策,删除记忆后诊断不留正文副本(查看时按 id 实时解析:生效中(脱敏内容)/已替代/已删除)。

## 架构

- **采集层在主窗**(`src/diag/`:types 白名单协议 / redact 脱敏 / store 环+派生结论),零抛错、零 IO;
- **派生结论是纯函数**(`deriveSummary`):未说话原因/回退链/取消泄漏/错误分类全部由事件流推导,错误章只在"错误是最终状态"时挂(重试成功、回退成功不挂);
- **跨窗**(settingsRemote + bridge):设置窗拉全量快照(`diag-snapshot` action)→ 收增量(`diag-upsert` 事件,进行中 1s 尾随节流、结束即时推);捕获/清空经 `diag-arm`/`diag-clear` 回传;
- **Rust CDP 阶段轨迹**(`webchat.rs` TraceBuilder + `webchat_last_trace` 只读命令):edge_ready → page_connected → ctx_stable → sent → first_busy → first_text → stable_done,每次 ask 后前端拉取挂到会话。

### 埋点位置(全部可选字段,不传不记,向后兼容)

| 模块 | 事件 |
|---|---|
| `ChatSession` | beginTurn(受理)/ memorySelection / toolsPrepare / actionFired / fallback(turnBatch 失败、流中断、空批)/ cancelRequested / turnFinished(各出口统一收口)/ backgroundFacts 的 memoryWrite |
| `llmClient` | llmStarted(call 标签=model/transport/prompt 结构/上下文行数/超时);streamVoiceReply 首句闭合;webchat 回退链;网页不支持流式的回退 |
| `llmGateway` | llmFinished(耗时/状态/错误分类)、llmFirstToken;**外部 abort reason 透传**——调用方内部超时不再伪装成用户取消(turnBatch 12s 超时因此能正确触发单句回落,而非静默丢弃) |
| `tts/index` | ttsRequest(epoch/channel/字符数)/ ttsSegment(demoted/dnd/开关/未配置/缓存命中/流式合成+播放耗时/降级/中断/stop-noop)/ ttsStopped;持密处注册真实密钥进脱敏池 |
| `webchat.ts` | llmFinished(webchat)+ 结束后拉 `webchat_last_trace` 发 webchatStages |
| `voiceSession` | ASR 成功指标并入本回合;失败/空结果开 mini 会话(否则「没听清」不可见) |
| `usePerformanceDirector` | play 起演出会话;onLineStart 逐句 actionFired + TTS 归组;插话 mini 会话;完播/中止定稿 |
| `liveDanmaku` | 每批弹幕一个会话;网页攒批失败回退 API 的 fallback 事件 |

## 边界(明确不做)

- 通用 trace.log(any) 接口;诊断数据落盘;麦克风音频/截图/工具二进制入诊断;默认档存任何可读正文。
