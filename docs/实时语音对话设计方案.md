# 实时语音对话闭环设计方案

> 麦克风 → VAD 起止检测 → ASR 转文字 → ChatSession → 流式回答 → 分句 TTS → 角色说话动画,
> 全程支持用户打断,界面明确「正在听 / 正在想 / 正在说」。
> 状态:已立项,按本文实施。姊妹篇:《对话系统设计方案》(文字链路)。

## 一、产品目标与体验基线

- **按键说话(PTT)**:按住全局热键说话,松开即送识别;任何阶段按下都可打断角色。
- **免按键模式**:VAD 自动判断说话起止;角色说完自动回到收音。
- **可切换 ASR**:云端(硅基流动,OpenAI 兼容 `/v1/audio/transcriptions`)先行,接口留本地 whisper.cpp 二期。
- **明确状态**:「正在听(带电平) / 正在想 / 正在说 / 麦克风不可用」。
- **延迟基线(保守)**:静音判定 0.6~0.8s + 上传+ASR 0.7~2.0s + LLM 首句形成 0.8~2.0s + TTS 首声 0.4~1.2s ≈ **首声 2.5~6.0s**;优化位:GPT-SoVITS 本地、TTS 缓存命中、首句边流边合成。

## 二、现状盘点(为什么大半条路已通)

| 环节 | 现状 | 结论 |
|---|---|---|
| TTS 合成+播放 | 三供应商流式合成、AudioWorklet 环形缓冲、两级缓存、通道仲裁、`speakTracked` 生命周期句柄、`prefetchVoice` 预取 | **直接复用**,仅加一个 `voice` 通道 |
| LLM | `llmGateway.complete()` 整包,已支持 `signal?: AbortSignal`;演出链已有 abort 先例 | 语音路径加 signal 透传 + SSE 流式变体 |
| 采集 | Rust 侧 WASAPI 环回(audio_capture.rs,`EventsShared{autoconvert:true}`);**无麦克风** | 新增 Capture 方向采集,范式照抄 |
| VAD/ASR | 无 | 新建,深模块 + 行为矩阵进 CI |
| 会话 | `ChatSession.send/cancel`(代次计数)、turnWindow、落盘双轨、事实提取 | 语音走同一入口,加 voice 路径 |

**关键架构决策:麦克风走 Rust 采集,不走 webview getUserMedia。**
WebView2 的 `PermissionRequested` 弹窗不可预授权、拒绝后难恢复(tauri#14753/#5042),对
WS_EX_NOACTIVATE 免激活桌面形态不可接受;wasapi crate 已在依赖中且 autoconvert 已实证可用。
VAD/状态机留在前端 TS 深模块——CI 可做确定性测试。

## 三、总体架构

```
┌ Rust ──────────────────────────────┐
│ mic_capture: 枚举/启停/owner/异常恢复 │  16k mono i16 裸 PCM 块(任意长度)
│   StreamMode::EventsShared{         │ ──Channel──────────────┐
│     autoconvert:true } 直接要 16k   │                        │
└────────────────────────────────────┘                        ▼
┌ 前端 engine ─────────────────────────────────────────────────────────┐
│ mic.ts 连续分帧器(字节余数→480样本帧,跨包不丢样) → vad.ts             │
│   · 300ms pre-roll 环形缓冲(speech-start 时回填,保住短促首音)         │
│   · 迟滞状态机:起=连续3帧超 noiseFloor+12dB;止=连续27帧(≈800ms)静音   │
│   · speech-end = 结束当前 utterance 缓冲立即送 ASR,麦克风不停          │
│ asr/: invoke asr_transcribe(wavBase64, model) → {text}               │
│ sentenceSplitter / llmGateway.completeStream(SSE) / llmClient.streamReply │
└──────────────────────────────────────────────────────────────────────┘
                        │ chat.send(text,{voice:true})
                        ▼
┌ 会话层 ────────────────────────────────────────────────────────────────┐
│ ChatSession(voice路径): 逐句 speakTracked('voice') → ended 后句级提交  │
│   每轮 AbortController;打断 = cancel() = 代次++ + abort + 句柄.stop()  │
└────────────────────────────────────────────────────────────────────────┘
```

### 状态(单一事实源,评审阻断项)

```
runtimeMode:   { type:'voice' }        ← 只管排他(caps 派生 voiceActive;canChat=false)
voiceSession:  off|listening|transcribing|thinking|speaking   ← phase 唯一持有者
VoiceStatusChip: 直订 voiceSession;transcribing/thinking 都显示「正在想」
```
voiceSession 对外 API 保持最小:`start(mode)/stop()/pttDown()/pttUp()/getSnapshot()/subscribe()`。

## 四、三个关键语义

### 4.1 真取消(不是"不再呈现")
每轮创建 `AbortController`,signal 贯穿 ChatSession→turnBatch/singleReply/streamTurn→
llmGateway(已支持)→endpointProxy→Rust `endpoint_cancel`。打断后 LLM 请求真正停止,
不烧额度、不与新轮并行。`cancel()` 同时调当前 `SpeechHandle.stop()`(epoch 守卫,只停本轮)。

**流式失败提交点**:
- 首句产出前失败 → 回落 turnBatch/单句(整段重生成安全,无任何上屏);
- 已上屏/已出声 ≥1 句后失败 → **保留已完成句、本轮结束**、气泡轻提示,禁止整段重生成(防重复回答)。

### 4.2 句级提交(打断后的聊天记录语义)
语音路径逐句:气泡随 `started==='audible'` 上屏('silent'→勿扰/静音,按文本节奏兜底),
**`ended` 后才 `recordTurn`**(短期窗口+落盘)。pending 提交槽只有一个:
- 播完的句子 → 提交;
- 播一半被打断 → 不提交;
- 未播的句子 → 丢弃;
- 用户打断时说的内容 → 下一轮正常消息。
半句音频时间点截断不做(SpeechHandle 无文本时间轴,需 TTS 字词对齐,二期)。

### 4.3 打断(barge-in)
- **PTT 打断恒可用**:speaking 期间按下说话键 → `chat.cancel()` → 回 listening。
- **自动 barge-in = 实验项,v1 默认关**:开启后阈值为「普通起声阈值再 +6dB」即
  `noiseFloor+18dB`、需持续 ≈400ms;UI 明示"外放可能误触发,建议耳机";
  风暴保护:10s 内 ≥3 次 <600ms 的误打断 → 自动退回仅 PTT。WASAPI AEC 二期评估后再定默认。
- **TTS**:新增 `TtsChannel 'voice'`,优先级同 chat(=0,语音回复不得压过提醒/工具播报);
  打断只调本轮句柄 `stop()`,不全局 `stopSpeaking()`;下一句预取走 `prefetchVoice()`。

## 五、模块设计

### Rust:`src-tauri/src/mic_capture.rs`(新,镜像 audio_capture.rs)
- `list_mic_devices() → [{id,name,default}]`(MMDevice 枚举,_capture 方向)
- `mic_start(owner, deviceId?, Channel)` — 16k/mono/i16 裸 PCM 块经 Channel 推送
- `mic_stop()` — 幂等
- **所有权**:单实例 + `owner: 'voice-session'|'settings-preview'`;voice-session 持有时
  设置页报错;voice 启动时预览在播则接管;Channel 断开(设置窗关闭)→线程自停;
- **异常恢复**:WASAPI 设备失效/休眠 → 线程退出并 `emit('mic-ended',{reason})`,
  前端进"麦克风不可用"态;应用退出 join 线程。
- `asr_transcribe(wavBase64, model) → {text}`:reqwest multipart 直发硅基流动,
  密钥 Rust 侧读凭据库 `asr:siliconflow`(能力级,**不依赖 TTS 已配置**);
  超时/响应上限/禁重定向照 endpoint_proxy 硬化;429 → "识别太频繁"。

### 引擎(`src/engine/`)
| 模块 | 职责 |
|---|---|
| `mic.ts` | 启停/帧订阅/连续分帧(余数缓存→480样本)/rms 电平 |
| `vad.ts` | VadEngine 接口 + 能量实现 + pre-roll + barge-in 参数 + 风暴保护;clock 可注入 |
| `asr/` | `AsrProvider` 接口 + siliconflow 实现 + local 桩(二期 whisper.cpp) |
| `sentenceSplitter.ts` | `feed(delta)→string[]`+`flush()`;句末标点断句,>24 字遇逗号即断,60 字硬顶 |
| `llmGateway.completeStream` | OpenAI 兼容 `stream:true` SSE 解析,plugin-http ReadableStream |
| `llmClient.streamReply` | 角色 prompt + 口头对话附加段;splitter 把 onDelta 变 onSentence;失败回落 turnBatch |
| `tts/index.ts` | 仅加 `'voice'` 通道一项 |

### 会话(`src/session/`)
- **ChatSession 扩展**:`send(raw,{voice?})`;voice 路径 = 逐句 speakTracked + 句级提交 +
  signal 贯穿;`streamTurn` 为可选 dep(默认 = turnBatch 逐句 yield,无流式也能跑);文本路径零改动。
- **voiceSession.ts(新)**:闭环编排器 + phase 事实源。listening→(speech-end)→ASR→
  transcribing→chat.send→thinking→首句出声→speaking→句排空→listening;PTT 模式松键即收。
  打断 = chat.cancel();mic-lost 恢复;进入前先停演出/主播,勿扰下照常(TTS 已静默)。

### 运行时/UI/设置
- runtimeMode 加 `{type:'voice'}`;`VoiceStatusChip.tsx` 直订 voiceSession;
- 入口:命令面板「开启/关闭语音对话」+ 全局热键 `toggleVoice`(可选);`pushToTalk` 为 hold 语义
  (hotkeys.ts 升级 Pressed/Released 双态派发,tap 动作不变;pttDown 幂等/换绑丢 Released 强制释放/
  30s  utterance 上限闩锁);
- 设置(VoiceSettings.tsx 加卡):模式分段/设备下拉/电平条+阈值线/自动校准/打断实验开关/
  ASR 供应商+模型(SenseVoiceSmall 免费、TeleSpeechASR、自定义)+测试连接(发 1s 静音 wav);
  configStore 扩 `VoiceConfig.voiceChat` + `AsrConfig`(密钥 `asr:siliconflow` 进 SECRET_FIELDS)。
