# 记忆事实 V3 设计方案(已实施)

> 核心不变量:**任意时刻,同一语义槽位只能有一个可注入事实;人工确认永远不会被普通模型提取静默覆盖。**

本文档描述记忆事实库(`memory.json` v3)的最终形态。它不重写 V2 的骨架——slot 白名单、
敏感度三源取严、确认窗、CAS 存储全部保留——而是补齐"证据权威"与"冲突审核"两层。

## 1. 分层结构

```text
用户发言 / 可信事件
        │
        ▼
MemoryIngestor(src/memory/ingestor.ts)
  pending 账本 → 提取 → 证据校验(摘录必须在原文中)→ 原子入库
        │
        ▼
MemoryPolicy(src/storage/memoryPolicy.ts,纯函数)
  authorityOf / supportOf / assessFact / decideFactUpdate / 查询冲突门控
        │
        ▼
MemoryStore(src/storage/memoryStore.ts)
  CAS 原子提交:事实 + 冲突 + 账本终态 一次 mutation
        │
   ┌────┴─────┐
   ▼          ▼
queryMemory  MemorySettings
安全注入      冲突卡 / 来源标签 / 原因三分
```

所有"用户发言 → 长期事实"的入口(ChatSession、legacyChat)都只调
`memoryIngestor.ingestUserTurn({ turnId, text })`,共享同一套可靠性规则。

## 2. 数据模型

### 证据(判别联合,权威的唯一事实源)

| kind | 字段 | 权威 | 支持度 |
|---|---|---:|---:|
| `user-edited` | text, at | authored | 1.00 |
| `user-confirmed` | at | confirmed | 0.98 |
| `verified-event` | eventId, provider, at(按 eventId 幂等) | verified | 0.95 |
| `explicit-command` | turnId, excerpt, at(识别后续接入,类型已备好) | explicit | 0.90 |
| `model-extraction` | turnId, excerpt, assertion(explicit/implicit/unknown) | explicit 提取→explicit / 其余→inferred | 0.72 / 0.55 |
| `legacy` | at | legacy | 0.50 |

- `assertion: 'unknown'` 只出现在 V2 迁移数据上(不伪造分级,按 implicit 档计分)。
- 模型提取必须带 `excerpt`,归一化后必须能在本轮用户原文中找到
  (`evidenceExcerptHolds`),否则候选被拒。
- `pinned` 只表示"常用/优先",不影响权威与支持度。

### 事实

不再持久化 `confidence / sourceTurnId / sourceExcerpt / lastConfirmedAt / hits`
(全部由 evidence 派生,避免字段互相矛盾);新增 `supersededBy?`。

### 冲突与账本

```ts
MemoryConflict { id, slot, existingFactId, proposed: FactProposal,
                 reason: 'lower-authority'|'ambiguous-change'|'confirmed-fact-changed', createdAt }
MemoryIngestRecord { id, turnId, status: 'pending'|'applied'|'skipped'|'conflict'|'failed',
                     candidateCount, appliedFactIds, reason?, createdAt, completedAt? }
```

账本只记 id/数量/枚举原因(不存正文),上限 150 条;冲突单上限 30 条。

## 3. 支持度与有效状态

- 不同回合的独立重申每个 turn +0.05;同一 `turnId` 重试不加分;纯模型提取封顶 0.90。
- `assessFact(fact, { now, hasOpenConflict })` 优先级:
  superseded → 冲突点名(conflict)→ 支持度 <0.5(low-support,仅防退化证据,
  legacy 恰 0.50 不触发)→ 超确认窗(expired)→ active。
- 时效基准 = 最近一次 user-confirmed/user-edited 的时刻;**聊天里再多提几次也不会
  绕过确认窗**——时效只认用户本人的手。
- 权威 ≠ 永不过期:用户亲自填写的住址仍要按 `profile.currentResidence` 的确认窗重确认。

## 4. 裁决矩阵(decideFactUpdate)

- 同 slot 同值(归一化,如 北京市=北京)→ merge:合并 evidence,权威/支持度只升不降。
- 同 slot 异值:
  | 旧事实 | 新证据 | 结果 |
  |---|---|---|
  | inferred/legacy | 明确陈述(explicit)/明确指令/可信事件 | replace |
  | inferred/legacy | 含糊普通提取 | conflict(ambiguous-change) |
  | authored/confirmed | 任何机器来源 | conflict(confirmed-fact-changed) |
  | authored/confirmed | 用户在设置页编辑 | replace |
  | verified | 可信事件 | replace |
  | verified | 提取/指令 | conflict(lower-authority) |
- 开放事实(无 slot)不做值替代:同文/高相似(双向 2-gram ≥0.85)merge,否则 coexist。

## 5. 原子摄取

一次摄取在**同一个 CAS mutation**内完成:规则闸 → 定位既有事实
(同 slot 任意值的 active 优先——V2 的值变化路径漏定位是双 active bug 的根源)
→ 裁决 → 冲突单(同 slot 只留最新一张)→ 账本终态 → 淘汰 → 提交。

冲突二选一(原子清冲突单):
- **保留旧值**:旧事实追加 `user-confirmed`;
- **改成新值**:旧事实 superseded(supersededBy 指向新事实),新值事实获得 `user-confirmed`。

`ingestVerifiedEvent` 按 eventId 幂等,适合未来直播会员身份等结构化事实;
userProfile(手填画像)继续直接注入,不复制进事实库。

## 6. 提取协议(V3)

模型输出每条事实必须带:
- `evidenceQuote`:逐字摘自本轮发言的原句证据(本地确定性校验,编造即拒);
- `assertion`:explicit(明确说出)/ implicit(间接体现)。

本地校验:quote 非空且在原文中;slot 必须在 `MEMORY_SLOTS` 白名单(非法 slot 降级为
开放事实,永不参与槽位替代);slot 有则必须带非空 value;单轮上限 3;不接收模型输出的
任何身份/来源 ID。敏感度三源取严(模型标注 ∨ 确定性正则 ∨ slot 注册表)与禁止规则
两道闸(prompt 前置 + 入库前)不变。

## 7. V2→V3 迁移(保守、幂等、不伪造证据)

- 证据映射:extracted → model-extraction(assertion=unknown);user-edited/user-confirmed/legacy 保真;无证据合成一条 legacy。
- 现存同 slot 多 active:保留权威最高者(平手取最近),其余转 superseded 并建冲突单
  → 迁移完成即满足单 active 不变量。
- 迁移只认 version 触发,对同一份已迁移数据再执行完全不变(不动点);topicStats/
  rules/counters/storyStore/userProfile 均不受影响。Rust 侧透明 JSON,无需改动。

## 8. 设置页

- **冲突卡**:仅在有冲突时显示,展示旧值/新值/来源摘录,[保留旧值][改成新值]。
- **来源标签**(不展示数字分):你亲自修改 / 已由你确认 / 由系统事件确认 /
  你明确要求记住 / 从聊天中记下 / 旧版记忆。
- **待确认原因三分**:可能已经过期 / 来源不够明确 / 发现了互相冲突的信息。
- **📌 文案**:"常用:提高被想起的优先级,不代表信息永远有效"。

## 9. 测试与验收

- `tests/memoryPolicy.test.mjs`(22 例):权威/支持度派生、裁决矩阵、查询门控、迁移映射。
- `tests/memoryLedger.test.mjs`(12 例):原子摄取、slot 冲突路径、冲突二选一、
  verified-event 幂等、迁移幂等、账本容量。
- `tests/memoryIngestor.test.mjs`(7 例):证据校验、同轮不加分/跨轮加分、
  非法 slot 降级、失败记 failed 不影响聊天、规则第二道闸。
- 验收对照:北京变上海不出双 active(#1)、人工事实硬保护(#2)、重申不降可靠性(#3)、
  同轮重试不加分(#4)/跨轮加分(#5)、摘录不在原文拒绝(#6)、非法 slot 不替代(#7)、
  低权威异值进冲突(#8)、冲突期间 slot 不被动注入(#9)、accept 带 supersededBy(#10)、
  keep 追加确认(#11)、verified-event 幂等(#12)、restricted 永不被动(#13)、
  确认不绕过时效(#14)、失败不影响聊天(#15)、单 CAS 原子提交(#16)、迁移幂等(#17)、
  话题口味/storyStore/画像不受影响(#18)。
