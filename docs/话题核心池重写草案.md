# 话题核心池重写草案 v3(定稿,已落码)

> v2 评审结论:positions 显式声明为无序二元组、分类下限补齐、残留预设结局清理、

## 内容数据模型(已实现)

```ts
interface TopicCard {
  title: string
  hook: string
  angles: string[]                     // 每条 2~4 个,压力条件而非标题换皮
  positions?: [string, string]         // 两种立场,无序二元组,顺序不代表角色槽位
  thirdParty?: {                       // 可选第三参与者(情境职能,非第三立场)
    role: 'catalyst' | 'witness' | 'affected' | 'mediator' | 'executor'
    instruction: string
    binding: 'cast-preferred' | 'external-only'
  }
  applicability?: {                    // 仅默认职业/世界观专属卡携带
    requiresPresent?: ActorSlot[]      //   如 C 包 requiresPresent:['C']
    personaSource?: Partial<Record<ActorSlot, 'default' | 'custom'>>
  }
  sensitivity: 'normal' | 'personal' | 'sensitive'
}
```

- positions 显式声明 86 处(覆盖全部"两种立场"卡);共同行动/共同保密等真对称卡不填;
  数组顺序不代表演员槽位,提示词明确"未预先绑定角色,按当前人设分配,必要时交换"。
- 核心池正文全匿名(标题/hook 零甲乙丙,CI 断言);甲乙丙只出现在条件加载的专属包。

## C 的三种运行状态(已实现)

| 状态 | 通用话题 | 默认 C 包 | 行为来源 |
|---|---|---|---|
| 启用+默认人设 | 参与 | 加载(6 条) | 可用默认特点;允许只做无声反应 |
| 启用+自定义人设 | 参与 | 不加载 | 全按自定义人设,不注入默认特征 |
| 关闭 | 新剧本完全移除 C | 不加载 | speaker 只允许 A/B;历史剧本照常回放 |

- 采纳链:config.characters.C.enabled → persona.setCEnabled(App 启动 + bridgeServer 差分)。
- castHash 覆盖:人设正文+来源+名字+性别+C.enabled,任一变化旧预生成立即失效。
- C 不进入 positions;默认 C 包 6 条按"情境职能"出演(整理桌面/冲突指令/玩笑当真/
  复杂规则/调停握有秘密/保守秘密过度谨慎)。
- 参与策略:cRuleFor 按基调分档——非喜剧 0~3 句且不要求每段开口、相声 0~2 句只垫梗,
  禁止 A→B→C 机械循环(协议层同步收窄 speaker 白名单)。

5. **周末计划与执行的落差** — 一人列了八项计划完成零项,另一人什么都没列却全干完了,复盘时双方都证据确凿。切口:计划本公开 / 下周计划由对方定 / 一项都不许删
