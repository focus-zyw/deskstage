# 招牌怪癖系统设计方案(设计定稿,未实施)

> 核心不变量:**模型只增不删,用户独享清除与锁定;怪癖是常驻的背景重力,不是每集任务。**

为角色引入"暗黑地牢式"怪癖系统:怪癖由模型生成(冷启动 + 从对话历史结晶)、逐角色最多三条、
用户可清除与锁定。怪癖解决的问题是**:默认人设是"类型"只给腔调,怪癖是"行为机制"自己产内容**——
它是"活的世界"的最小实现,不需要建模拟器,并且与记忆事实 V3 共用"对话 → 沉淀 → 反哺对话"的闭环。

灵感与对照:RimTalk(jlibrary/RimTalk)的 persona 生成配方(说话方式 + 态度 +
**一个让人过目不忘的怪癖,要具体、大胆,避免无聊特质**)与其 48 个内置原型的
"态度 + 具体行为画面"两句式;暗黑地牢的怪癖三精髓——来自经历、有正负价、用户有疗养院(锁定/清除)。

## 1. 目标与非目标

**目标**
- 角色 A/B/C 各自持有 0~3 条结构化怪癖,持久化、跨重启稳定。
- 两条生成来源:冷启动(按人设生成)与结晶(从近期对话沉淀),共用同一套生成协议。
- 怪癖注入主演出 prompt;表达导演的 callback 旧梗系统获得第二只读梗源。
- 用户可在设置页清除、锁定怪癖;新怪癖获得时在群聊房间公示一条系统消息。
- 全程实验开关,默认关。

**非目标(v1 不做)**
- 不做怪癖的模型侧删除/修改(权限矩阵不允许)。
- 不做短通道(戳一戳/单聊)与网页群聊增量轮的怪癖注入(P3 再评估)。
- 不依赖"角色侧长期记忆"入库(等记忆 V3 角色侧事实落地;v1 由近期互动摘要扛)。
- 不做怪癖强度升级/怪癖合成等 DD 深水区机制。

## 2. 数据模型

```ts
interface QuirkEntry {
  id: string                 // 生成即定,cuid/uuid
  trigger: string            // 触发情境(一句,具体)
  behavior: string           // 可观察行为(一句,具体)
  valence: 'red' | 'blue'    // red=怪/执拗/冲突向;blue=温柔/仪式/陪伴向(非负面/正面)
  type: '触发式' | '仪式式' | '规则式' | '积累式' | '观察式' | '防御式' | '社交式'
  cause: string              // 一句因果(小经历留下大习惯);本身是可回收的谈资素材
  source: 'cold' | 'crystallized'
  locked: boolean            // 用户锁定;锁定者不参与让位
  createdAtEp: number        // 主演出集计数(获取时刻)
  lastUsedEp: number         // 导演/注入侧冷却记账,未用过为 -1
}
```

- 存储:configStore 结构化键 `quirks: { A: QuirkEntry[]; B: QuirkEntry[]; C: QuirkEntry[] }`,
  与 `expressionV2` 同文件同模式。数据量小(≤3×3 条)、写入低频、无并发冲突,不需要 memoryStore 的 CAS。
- 上限:每角色 3 条,由存储层硬约束(超限写入直接拒绝)。

### castHash 注意事项

`persona.ts` 的 `castHash()` 是预生成剧本缓存兼容令牌("阵容变了,旧剧本不得再播")。
**怪癖不进 castHash**:怪癖是动态状态,获取/清除不应作废已排队的剧本缓存;
它只影响之后的生成。此偏离于实现时在 castHash 处加注释说明。

## 3. 权限矩阵

| 操作 | 模型 | 用户 |
|---|---|---|
| 新增(冷启动/结晶) | ✓(自动,获得时公示) | — |
| 删除 | ✗ 永不 | ✓ 清除 |
| 锁定 | ✗ | ✓(锁定后自动让位不能动它) |
| 修改既有怪癖文本 | ✗ 永不 | v1 不做(清除后重生成即可) |

- 上限让位规则:新增时若已满 3 条,**未锁定的最旧一条让位**(按 createdAtEp),被让位者静默移除;
  全部锁定则本轮放弃生成(不提示不打扰,用户解锁后下个周期自然补上)。
- 生成与写入原子:解析失败/校验失败直接放弃,不产生半条怪癖。

## 4. 生成协议(两条来源共用)

### 4.1 触发时机

| 来源 | 时机 | 输入差异 |
|---|---|---|
| 冷启动 cold | 开启系统后某角色怪癖为空时,惰性触发一次 | 经历/互动槽可为空 |
| 结晶 crystallized | 每 N 集主演出结算一次(N 默认 10,可配);槽位有空且距上次生成 ≥M 集(M 默认 5) | 近期互动摘要 + 因果存档 |

结晶调用走既有单次 JSON 查询通道(同 persona 生成/蒸馏的 `Query` 形态),
失败静默放弃,本周期不再重试——怪癖获取是馈赠不是任务,绝不能为它阻塞演出链路。

### 4.2 输入槽映射

| prompt 槽位 | 来源 | v1 状态 |
|---|---|---|
| `{name}` / `{pronoun}` | persona.ts `nameOf` / `pronounOf` | 就绪 |
| `{persona}` | `personaText(id)` 全文 | 就绪 |
| `{quirkList}` | 该角色既有怪癖(trigger+behavior+valence) | 就绪 |
| `{recentDigest}` | chatlog 尾部 / 最近几集场景卡摘要(复用既有摘要产物) | 就绪 |
| `{causeArchive}` | 该角色历次怪癖的 `cause` 累积 | 就绪(冷启动为空) |
| 角色侧长期记忆 | 记忆 V3 角色侧事实 | **未就绪,槽位留空** |

### 4.3 prompt 模板(定稿)

v3 用户稿 + 四补丁(输入槽、代词模板、防克隆声明、type 字段)合并后的最终形态:

```text
根据角色「{name}」的人生经历、长期记忆和近期互动，生成一个可能自然形成的招牌怪癖。

【角色设定】
{persona}

【已有怪癖】（新怪癖不得与之同域）
{quirkList 或"(无)"}

【近期互动摘要】
{recentDigest 或"(暂无)"}

【经历与因果存档】
{causeArchive 或"(暂无,因果可虚构)"}

这里的“怪癖”不是普通性格、兴趣或偏好，而是：
当某类具体情境出现时，角色会近乎条件反射地做出一个有辨识度、可反复出现、稍微不讲道理却符合{pronoun}人生经历的行为。
目标是让用户只看到这个行为，就可能想到“这确实是{pronoun}会干的事”。

要求：
1. 必须是“具体触发 → 具体行为”。trigger 必须是日常对话里真实可能出现的事件、词语、动作、物品或情境；behavior 必须是别人能观察到的动作、话术、仪式、执念或反应；禁止写成抽象心理状态。
2. 必须有画面感。优先选择：奇怪的小仪式 / 固执的固定流程 / 条件反射式反应 / 不必要但坚持要做的事 / 自创规则、称呼、计量方式或判断标准 / 对某类小事异常认真。
3. 要大胆，允许“不太正常”。宁可生成一个“有点离谱但合理”的行为，也不要安全、温和、谁都可能有的习惯。
4. 怪癖必须带一点“不可控感”：明知道没必要，{pronoun}还是很容易这么做。最好让角色因此偶尔显得麻烦、嘴硬、较真、幼稚、可爱或莫名其妙。
5. 禁止普通性格标签和普通爱好（喜欢/讨厌/害怕/有点/比较/经常 XX，喜欢收集东西、爱吃甜食、讨厌加班、比较爱干净、有强迫症等），除非进一步表现成一个非常具体、独特的行为。
6. 触发情境必须可复现，优先聊天中能反复出现的生活切口；不要依赖极罕见事件（遇到流星、被困电梯、参加婚礼等）。
7. 优先从具体人生经历中建立因果：像经历留下的“后遗症”“习惯”或“私人逻辑”。因果可以合理补全，但不得与已有记忆冲突，不凭空创造重大人生事件，最好是“小经历留下大习惯”而不是戏剧化创伤。
8. 不要破坏核心人格：怪癖放大角色已有的一角，而不是重新创造一个陌生人格。
9. 一句就能说清：trigger 和 behavior 都要短、具体，不要解释、铺垫、写故事。
10. 与已有怪癖的关系：不得是同义改写、换一个物品、换一个触发词或强度升级版；可以互相呼应，但必须表现角色的另一个侧面。
11. 输出前先自检淘汰：放到别的五个角色身上也成立 → 太普通，换；用户看到一次就忘 → 换；只能靠解释才显得有趣 → 换。

参考水准（仅参考结构与水准，禁止沿用其中的物品、场景或句式）：
- 听见塑料膜摩擦声，就必须把手边气泡全部捏完才肯继续说话。（触发式·红）
- 每批临期饭团都会按“资历”起外号，“元老”被买走后会郑重宣布它毕业了。（积累式·蓝）
- 别人说“随便”时，会立刻列出三个选项逼对方正式弃权，否则拒绝替他决定。（规则式·红）
- 每次别人准备出门，都会按“钥匙、手机、命”三项检查一遍，第三项永远一本正经。（仪式式·蓝）
- 看到聊天框里连续三个句号，会默认对方情绪出问题，开始偷偷改变说话语气。（观察式·蓝）
- 自己说错话后绝不立刻认错，而是先纠正一个完全无关的小细节，过几句才若无其事补偿。（防御式·红）

勉强合格 → 更好：
- 紧张时会反复整理桌面 → 心虚时会突然把桌面图标按大小重新排一遍，排完才肯继续聊
- 喜欢给东西起名字 → 只有快过期的食物才有资格获得名字，而且越接近过期名字越正式

valence：red=更偏怪、执拗、麻烦、荒谬、嘴硬、强迫感（易制造喜剧冲突）；blue=更偏温柔、可爱、仪式感、珍惜、积累感（易制造陪伴感）。不是负面/正面之分，两类都要有鲜明辨识度。

只输出 JSON，不要解释，不要 Markdown：
{"trigger":"情境","behavior":"行为","valence":"red|blue","type":"...","cause":"一句简短因果"}
```

模板以纯函数组装(输入槽替换 + 代词),进测试体系。反套路承重条款是**第 11 条可迁移性测试**
(将来精简 prompt 不得删除);第 3+8 条与刻板印象张力由第 11 条仲裁。

### 4.4 校验

代码侧只做结构校验(五字段齐全、valence/type 在枚举内、trigger/behavior 非空且长度上限),
**不做语义去重**——同域判定靠 prompt 第 10 条 + 用户清除兜底,不引入 embedding/LLM 评审调用。

## 5. 运行时

### 5.1 注入(主演出)

- 注入点:`fullPersona()` 在角色行后追加一行怪癖摘要(≤3 条,每条"trigger→behavior"并句):
  `招牌怪癖(背景重力,偶尔自然触发,不是每集任务,禁止逐集报菜名):…`
- 纪律:措辞明确"重力不是任务",防模型每集强行提怪癖;怪癖是可供模型随时摸一把的常驻素材。
- 短通道(solo/duo)与网页群聊 v1 不注入(P3 评估)。

### 5.2 表达导演接线

- 怪癖登记为 **callbackPicker 的第二只读梗源**,与 story.json 旧梗同一模式:
  ChatSession 侧只读预选(怪癖候选随 chainExtras 下发),不写注入冷却、不烧主演出额度。
- 冷却记账:`lastUsedEp` 由提交侧回写;**同型不连集**——上集用过 `type` 相同的怪癖梗,本集预选降权。
- 与口头禅冷却/旧梗冷却互不挤占,各自独立记账。

### 5.3 公示

获得怪癖时向群聊房间写一条 control 消息(`roomJournal`,`kind:'control'`,UI 渲染为"系统"):
`「{name}」长出了新怪癖:{behavior}`。冷启动首条与结晶获条都公示;让位不公示(静默),
清除是用户操作无需公示。公示把内部状态变化变成演出材料,兼做存在感声明,替代"每集报菜名"。

## 6. UI

- 设置页人设区(或 expressionV2 实验卡片旁)新增怪癖区:每条怪癖一张卡,
  红蓝描边 + 类型标签 + 来源标注(冷启动/结晶/集数),操作:锁定切换、清除。
- 满员时清除按钮旁提示"3 条已满,新增会顶替最旧的未锁定条目"。
- 总开关 `quirkSystem` 关闭时整区隐藏,存量数据保留不清除。

## 7. 配置开关

configStore 增 `quirkSystem: boolean`,按 expressionV2 三处规范改法:
类型声明(≈:279)、默认 false(≈:462)、normalize `(v) => v === true`(≈:1136);
UI 挂 PrivacySettings 实验卡片(同 expressionV2 ≈:205 模式)。默认关。

## 8. 测试计划

| 组 | 用例 |
|---|---|
| 存储 | 往返持久化;上限 3 硬拒绝;让位跳过 locked、全锁定则拒绝;清除/锁定 |
| 生成 | JSON 五字段解析;枚举外值拒收;解析失败静默放弃且周期内不再试;让位与写入原子 |
| 注入 | fullPersona 拼接(满/空/关);**自定义人设角色:不注入默认人设,但结晶怪癖照常注入**;prompt 纯函数快照(槽位/代词替换) |
| 冷却 | lastUsedEp 回写;同型不连集降权;与旧梗/口头禅记账互不干扰 |
| 公示 | 获得恰一次;让位不公示;开关关不发 |
| 回归 | 开关关 = 现行为逐字节一致(同 expressionV2 回归法) |
| 反AI腔 | craft 行存在性;闸扩展模式命中/不误杀(见附 A) |

## 9. 分阶段落地

- **P0 调品(零代码)**:用 §4.3 模板手动给三角色各跑 5–10 次,测平庸率/克隆率/红蓝比;
  产出不满意先改 few-shot,不动代码。这是整个系统的口味闸门。
- **P1**:开关 + 存储 + UI + 冷启动生成 + fullPersona 注入 + 公示;附 A 反 AI 腔三行同车
  (独立于本开关,直接常开)。
- **P2**:结晶来源(每 N 集结算)+ 导演 callback 接线 + 同型冷却。
- **P3(可选)**:短通道/网页群聊注入、记忆 V3 角色侧事实接入 `{角色长期记忆}` 槽、
  qualityGate slop 扩展。

## 10. 开放问题

1. N/M 默认值(10/5)待 P2 实测调整。
2. UI 归属:人设区 vs 独立实验卡片区,P1 实现时定。
3. webchat 增量轮怪癖提示是否走 expressionLine 顺带携带(P3)。
4. 近期互动摘要的产物形态(复用现有摘要 vs 新做 chatlog 尾部裁剪),P2 定。

## 附 A:反 AI 落腔指令落地(独立小改动,随 P1 常开)

RimTalk 原句 "casual, grounded, concise; avoid poetic filler, dramatic narration,
or generic AI slop" 的中文化原则:**不直译 "AI slop",枚举表层形态**——中文模型对
"AI 腔"没有共享所指,写具体示例模型才知道躲什么。每处控制在三四个示例,再多吃注意力。

### A1. promptBuilder.ts 非喜剧 craft 块(≈:248,平淡问题最重处)

在"台词全部口语化"行后追加:

```
- 像真人说话，短而落地：每句只说当下这件具体的事；不写抒情比喻和戏剧旁白（"仿佛""空气凝固了"式），不上价值、不升华点题（"这大概就是…吧"式收尾），少用"其实/说实话/不得不说"这类万金油开头
```

### A2. promptBuilder.ts 喜剧 craft 块(≈:245)

slop 在喜剧里的形态是铺垫冗长与书面转折:

```
- 不写无信息的比喻和抒情，不上价值不总结；"值得一提的是/不得不说"这类万金油开头一律不要
```

### A3. groupChat/actorPrompt.ts disciplineBlock(≈:100)

```
- 像真人打字：短句为主，不用书面腔和万金油连接词，不抒情不上价值
```

注:网页增量轮不注入纪律块,靠站点会话内既有规则存续;此行只影响全量轮/恢复轮,足够。
单聊短通道(soloShortPersona 调用方)同理套用。

### A4. qualityGate 扩展(可选,P3)

现有 `SERVICE_TONE_RE` 只拦助手身份泄漏。可扩 slop 专属 blacklist:

```
值得一提(的是)|不得不说|在这个快节奏|引发了(人们的?)?(深思|思考)|归根结底
```

**边界**:`其实/说实话` 在真实口语高频出现,只能进 prompt 层劝阻,**禁止进闸层删除**,
否则误杀自然台词。修复策略沿用"整句剔除、恰好一次"。
