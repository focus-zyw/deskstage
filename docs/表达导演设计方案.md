# 表达导演设计方案(ExpressionDirector)

> 阶段一已落地(群聊接入 + `expressionV2` 灰度开关,默认关);阶段二/三为规划。
> 方案来源:用户提供的《表达导演模型》设计稿;本文按仓库文档惯例改写并记录落地偏离。

## 1. 目标

保留群聊调度、记忆、情绪与演出系统,在"角色收到消息"和"模型生成文字"之间增加
统一的表达导演模块:导演决定这轮"怎么说"(动作/立场/长度/旧梗),模型只负责把
决定写成自然台词。解决三类病:回复长度与手法千篇一律、角色辨识度靠口头禅堆砌、
梗与情绪只有主演出有而群聊没有。

## 2. 现状判断(落地前)

- `GroupChatRuntime` 已是合格的深模块:队列、ACK、并发、预算、停止规则齐全,**不动**。
- `autonomyPolicy` 管"能不能说",新模块管"怎么说",两者不混。
- `src/groupChat` 按设计"没有导演"——表达导演是第一个 per-turn 规划模块,
  但只提供"怎么说"的计划,不参与"谁说话/何时说话"的任何裁定(runtime 头注释同步)。
- 群聊 prompt 此前没有每轮变化的指令通道;WebChat Adapter 复用远端会话,
  fullContext=false 的增量轮不会重发人设块——**表达指令必须走每轮必达的通道**。

## 3. 核心设计:深模块 src/expression/

```
src/expression/
├── director.ts          # 唯一编排入口:plan / noteSpoken / learn / recentTraces
├── policy.ts            # 动作选择、基础权重、全部冷却规则(纯函数 + 显式 PolicyState)
├── voiceProfile.ts      # 人设 → 说话机制(VoiceMechanics);自定义人设确定性派生
├── callbackPicker.ts    # 只从宿主提供的真实旧梗中选相关项(绝不编造)
├── promptRenderer.ts    # 结构化 Plan → 中文指令(确定性模板,无模型调用)
├── qualityGate.ts       # 重复/客服腔/复述/超长/连续反问/口头禅冷却 + 恰一次轻修复
├── preferenceStore.ts   # (角色,动作) 赞踩计数 → 权重乘数(阶段三接 UI)
├── types.ts             # 领域类型与长度档
└── index.ts             # 唯一公共出口(桶文件,seam 收口,照 src/topic 惯例)
```

接口(与设计稿的差异见 §10):

```ts
interface ExpressionDirector {
  plan(input: ExpressionInput): ExpressionPlan          // 同步,<2ms,零模型调用
  noteSpoken(e: { trace; text; personaText? }): void    // 提交成功后记账(新增,见 §10)
  learn(e: { trace; rating: 'up'|'down' }): Promise<void>
  recentTraces(actor?): ExpressionTrace[]
}
```

关键不变量:
- 不能越过 `maySpeak=false` 强迫角色发言(worker 侧:maySpeak=false 根本不调 plan)。
- 规划失败回退普通直接回答策略,绝不阻断聊天(plan 内部全捕获)。
- 每轮最多一个意外表达动作(单轮单动作;surprise='mild' 仅标 absurd-leap/literalize)。
- 旧梗只能从输入提供的真实记忆选择(story.json 只读预选,不烧主演出注入冷却)。
- 冷却只认"提交成功"(noteSpoken 推进),规划/重试/网页恢复重建不虚增回合。

## 4. 领域模型

- `ExpressionMove` 10 个动作:direct/tease/challenge/absurd-leap/literalize/
  callback/deflect/vulnerable/pivot/close。基础权重 35/15/10/10/7/7/6/4/4/2,
  **由代码抽取**,绝不让模型自己遵守"20% 概率"。
- `ExpressionStance` agree/neutral/doubt/disagree;`ExpressionIntent`
  answer/react/ask/defend/shift/close。
- `ExpressionLength` 三档:micro 2~12 字 / short 8~30 字 / medium 20~60 字、
  最多三短句;群聊协议 80 字硬上限(REACTION_TEXT_MAX)不变,plan.constraints.maxChars
  取档位与通道上限的较小值。
- `ExpressionTrace` 仅枚举与 id、无正文(隐私红线与 diag 一致)。
- `VoiceMechanics`(方案 §四):rhythm/social/humor/defense/forbiddenPatterns。
  内置 A/B/C 三套与 persona.ts 四维画像对齐(B 即方案示例值);自定义人设
  **确定性关键词派生 + 中性基线**,不把默认人格强加回自定义角色(分层纪律同款);
  口头禅解析不出给空表,冷却自动失效,不猜不编。

## 5. 决策与渲染路径

```
decidePlanCore:
  detectTask(用户明确任务)→ 强制 direct + mustAnswerTask(先答任务再发挥)
  防御反应:defense.trigger 字面命中 stimulus → 改用 defense.response(仍受冷却约束)
  eligibleMoves(全部冷却规则)→ weightOf(humor×1.6/列表外×0.7、teasingIntensity、
  initiative、偏好乘数)→ weightedPick(rng 注入)
  → stance(agreementBias 分布)→ length(preferredLength 分布)→ intent
promptRenderer:
  结构化 Plan → 3~7 行中文指令("本轮表达策略(执行即可,不得复述):…")
```

冷却规则(方案 §三全量):同动作最多连两次;callback 间隔 ≥6 个该角色回合
(从未使用不设冷却);口头禅间隔 ≥8 回合(noteSpoken 在上屏文本里逐字检测生效);
不能连续两轮反问(mayAskQuestion=false 禁 challenge);absurd-leap 与 literalize
互斥(单轮单动作天然满足,相邻轮也互歇)。

## 6. 群聊接线(阶段一)

```
actorWorker.buildRequest()
  extras(factsLine/briefLine/toolNotes/gags) → maySpeak hint
  → ExpressionDirector.plan(stimulus/recent/gags/personaText/limits)
  → PromptBuildInput.expressionLine → systemContent 两种形态都追加(PROTOCOL_RULES 之后)
  → ActorModelAdapter.react()
  → qualityGate(至多一次轻修复,只动 reply.text)
  → router.commitActorResult(…, meta{expression, gateIssues})
  → ChatSession.onCommit → chatlog trace 槽(仅调试档 memoryDisplay==='debug' 落)
```

- 注入点:`actorPrompt.systemContent` 的 fullContext 与增量两个分支都追加——
  WebChat 增量轮/两段式恢复重建每轮必带(远端会话复用,不能放 fullContext 块里)。
- 旧梗来源:`ChatSession.send()` 里 `peekStory + selectStoryItems(1)` 只读预选,
  随 chainExtras → prepareExtras 进 worker;不调 commitStoryInjection。
- provider 形态:`expression?(): ExpressionDirector | undefined`,每次调用取最新开关;
  返回 undefined = 关闭,不规划、不注入、不过闸、不记账,prompt 与旧版逐字节一致。
- trace 通路:`commitActorResult` 可选第 4 参 meta → onCommitted → onCommit meta ——
  trace 必须在落盘时刻可用(worker await 之后补传会晚于落盘)。

## 7. 质量闸(方案 §九)

检查:与该角色最近 6 条回复全等或 bigram 相似度 ≥0.8(repetition)、客服腔黑名单
(service-tone)、整句复述用户原句(echo)、超长度计划(over-length)、连续反问
(question-ban)、口头禅冷却未结束(catchphrase-cooldown)。

契约:`GateResult.issues` 反映**修复后最终文本**的问题。轻修复恰好一次:
句边界截长(找不到句读硬截)、整句剔客服腔、疑问尾改陈述、字面去口头禅;
repetition/echo 不可修。**永不阻断聊天**:修不掉照常提交(router 自身的重复护栏
仍会判重复降级 listen),绝不重新生成(即时聊天 P95 延迟红线 +300ms;规划纯本地,
实测均值 ≪2ms)。

## 8. 反馈学习(阶段三接 UI,阶段一就位)

`(角色,动作) → {up, down}` 计数;`score=(up+1)/(up+down+2)` 拉普拉斯平滑
(零反馈=乘数 1);`multiplier=clamp(0.6,1.5,score×2)`——任何单一动作权重至多 ±50%。
**direct 永不可学**(回退与任务通道不能被踩没);任务优先、maySpeak、用户指令权同样
不在可学习集合。存储照 feedbackStore 模式 B(withFileLock + localStorage 降级),
IO 可注入;阶段一无写入端,乘数恒 1,行为与未学习完全一致。

## 9. 分阶段落地

- **阶段一(本次)**:src/expression 全量;只接默认群聊 Actor 管线;`expressionV2`
  配置(configStore 三处:类型+默认 false+清洗器 `v=>v===true`)+ 设置页实验开关
  (PrivacySettings「表达导演」卡);34 个行为测试;本文档。
- 阶段二:接旧聊天/插话/直播弹幕/空闲发言;固定"15~25 字"改读长度档;
  赞踩 UI(聊天气泡小型入口)。
- 阶段三:表达偏好学习生效闭环;主演出拆 PerformanceWriter(场景规划 + 台词创作
  两遍生成);删除被取代的分散 prompt 规则;保存人设时由模型生成结构化
  VoiceMechanics(照 modeGenerator 模式:LLM → 严格清洗 → 坏数据拒存)。

## 10. 与设计稿的偏离记录

| 设计稿条目 | 落地 | 理由 |
|---|---|---|
| 接口只有 plan/learn | 增 `noteSpoken`(记账)与 `bannedCatchphrase`(plan 字段) | 冷却只认提交:规划/重试/恢复重建不虚增回合;质量闸需与指令同源的禁用词 |
| 注入方式未定 | `ActorWorkerDeps.expression?()` provider | 与 `identity()` 同风格,每次取最新开关;关=undefined=零行为变化 |
| ExpressionInput 固定 | 增 `personaText?` | 自定义人设的 VoiceMechanics 派生输入 |
| mood 进输入 | 阶段一不接(恒 undefined) | 群聊现无情绪注入通路;避免为可选项扩 prepareExtras 契约 |
| 口头禅/旧梗冷却未定实现 | 冷却状态由导演内存记账,口头禅从上屏文本检测 | 无处可挂"每轮结束"事件;提交成功是唯一可信节拍 |
| chatlog trace(设计稿排二阶段) | 提前到阶段一 | 近重复率/辨识度验收需要观测数据;仅枚举与 id,调试档才落 |

## 11. 测试(tests/,Node 原生 runner + vite ssrLoadModule,假依赖零 IO)

  冷却、指令渲染逐行。
- `expressionDirector.test.mjs`:计划结构与约束、异常回退不阻断、<2ms 耗时预算、
  noteSpoken 记账与口头禅冷却、偏好乘数公式与 direct 拒学、质量闸六类检测与恰一次
  修复、expressionV2 配置清洗。
- `expressionActorWiring.test.mjs`:开关开注入/关=旧版逐字节一致、maySpeak=false
  不规划、超长截长后提交、不可修重复照常提交+gateIssues 穿出+router 降级 listen、
  网页增量轮与恢复重建携带指令、extras gags/personaText 进导演输入。

## 12. 边界(明确不做)

- 不改 ActorReaction 输出协议;API/WebChat Adapter 不改;ACK/并发/预算规则不改;
  presenter/TTS 不改。
- 导演不决定谁说话、何时说话、说几条;不越过 maySpeak;不生成台词,只生成指令。
- 不做整段重写式修复;不做远程调用;阶段一不接演出/插话/直播/空闲通道。
